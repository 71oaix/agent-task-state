# 六项 Agent 研究工作的统一分析表

最后更新：2026-11-09

研究目标： 不以记录字段的多少评价工作，而是比较它们解决的根本问题、建立的机制、带来的系统价值，以及对构建一个可靠的长期 Agent 任务状态系统还有哪些不足。

本次统一采用以下分析逻辑：

核心问题 → 解决机制 → 记录要素 → 主要贡献 → 关键缺陷 → 继承或舍弃

其中，“关键缺陷”主要指相对于我们希望构建的完整任务状态系统，现有工作尚未覆盖的能力，不一定是论文作者自身目标上的失败。

另外，六项工作并非全部属于同一种研究成果：ATIF 是格式规范，Execution Provenance 是综述，另外四项是论文或系统方案。因此不能直接用同一套实验指标判断优劣。

## 从统一分析表中提炼出的结论

这六项工作实际上分别解决了六种不同的失败：

ATIF

执行历史不可互通

价值：让真实执行过程能够被统一保存和重读。

AgentOps

系统内部不可观察

价值：让运行中的关键组件、阶段和错误能够被定位。

ESAA

权威状态容易损坏

价值：让状态变化受到可靠机制约束，并且能够重建。

Execution Provenance

不知道结论为何成立

价值：让证据、判断与行为之间建立可追溯联系。

EMG

试错经验无法有效复用

价值：让成功与失败之间的差异成为可利用的经验。

Zep

长期信息产生冲突和过期

价值：让信息具有来源、历史和时间有效性。

但这里有一个值得警惕的地方：解决六种失败，不代表必须建立六套互相独立的机制。

例如，ATIF 与 AgentOps 的运行记录可能共享同一底层证据；EMG 所需的试错信息，可以从统一的历史与任务关系中派生；Human View 和 Agent View 则都不必成为独立维护的真相。

因此我们接下来应当研究的是这些能力的共同依赖与复用关系，而不是把六项工作平行装进一个系统。

## 对我们未来系统的初步推论

![image-20261009172001637](C:\Users\10636\AppData\Roaming\Typora\typora-user-images\image-20261009172001637.png)

这是从相关工作推导出的候选架构，不代表上述论文已经实现了这套完整系统。

其中，最有可能体现我们增量价值的是中间尚未充分解决的部分：

可靠的语义依赖管理——不仅知道一个判断依赖哪些证据，还能在证据失效时，自动识别哪些决策、计划和派生状态必须重新审查。

它可以进一步结合 Git/JJ 的版本演化、Bazel 等构建系统的增量计算、数据库的事务与一致性机制，形成一个真正可运行的任务状态引擎。

不过，这目前仍是候选研究方向，不是已经证实的创新点。需要进一步验证：现有系统是否已经具备类似能力，以及新增机制带来的收益是否超过其复杂性和维护成本。

最终，我们想追求的并非六项工作的简单相加，而是：

\[ \boxed{ \text{最小可信事实核心} + \text{可靠依赖管理} \longrightarrow \text{丰富且可重建的系统能力} } \]

这张表可以作为第一版相关工作比较的基础。下一步最值得研究的不是增加字段，而是提炼整个系统必须始终满足的不变量（无论系统如何运行都必须成立的规则），再寻找实现这些不变量所需的最少机制。
