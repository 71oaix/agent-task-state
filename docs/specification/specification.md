# 项目语义状态管理：实验协议与规格入口

本入口记录已确定的首轮研究协议和待验证的系统行为。研究对象与成功判断见[研究意图](../intention/intention.md)。具体状态机制、正式样本规模和判定阈值仍待验证，当前尚无批准的系统规格及实现交接。

## 首轮实验协议

- **主协议采用逐题揭示、保留同一会话。** 同一路径上的后续问题在上一题完成阶段记录后才提供。各组从相同起始快照开始，带入各自前序的代码与状态，每题结束保存代码、项目知识和可观察行动。Agent 可自行运行任务内测试，独立评分与参考答案留在评估侧。
- **整链一次给齐用于论文对齐。** StateHarness v1 在单次请求中给出全部题目，产出一个总补丁再逐题评分。它和原 ChainSWE 同时存在给题时机、会话边界、提交和评分的差异。要单独测给题时机，两边应保留相同会话策略、阶段快照、评分和反馈规则。逐题重开会话留作跨会话复用的独立条件。
- **对照统一使用 Pi 和本项目自选的工作模型。** 先验证原生 Pi 与忠实移植的 StateHarness 参考版，再按构建、维护、使用一次替换一环。正式比较固定项目快照、任务顺序、模型和预算口径、工具权限、评分器及测试反馈。启动协议、提示注入、上下文压缩与诊断策略的移植差异须可查。若参考版依论文重写、某个行为无法复核，标明偏差和影响。

## 观察与评分

构建对照给相同原始证据，检查记录的准确性、覆盖和适用范围。维护对照从相同初始知识出发，观察新需求或变更出现后，哪些旧结论被找到、保留、修订或标为待验。使用对照提供相同且正确的知识，比较相关信息是否在决策时被找到、正确理解并落实。端到端运行保留 Agent 的原始回写，在两次相关变更之间独立核对写入保真度，再用原始回写继续下一轮。失败时可另做一次诊断运行，只补给证据或修正错误回写，区分发现、判断、行动和写入失败。

案例应包含仍有效、需要复核和证据不足的结论，以及复验成本足以影响选择的实际决定。优先使用真实时点可见材料，按提交及可查记录定界，防止后续题目、测试答案、参考补丁和评价泄漏。若加认真维护的普通文档基线，先按预定规则仅使用当时材料编写，再选具体变更。T12 适合校准概念，若作为正式样本，需重建真实决策时点并取得独立裁决证据。

任务完成、原有行为回归和测试缺失分别记录。另记录知识质量、漏验、可避免的复验，以及声明待验并限制交付范围的情形。成本包含工作模型与辅助诊断、工具与测试耗时、状态维护及重试。一个案例用于检验这些差异能否被观察和裁决。正式样本量、效应阈值和统计方法应由校准结果决定。

每组分别记录 Agent 是否正常交卷，以及截止时补丁的独立评分。上游额度中断仍可评估已保存的补丁。时长和完成率按实际退出原因解释。三组完整链对照固定模型线路，同模型名下的不同线路分别归档。

## 实施顺序与开放设计

1. 已用公开 ChainSWE 的固定镜像、上游补丁与独立评分器完成环境校准。原生 Pi 和按作者源码移植的 A4 已完成两条链的逐题探查。作者额外对照配置和 RefactorBench 保留为候选。完整复现作者旧样本另需对应载荷和协议。
2. StateSystem v0.1.0 是当前维护对照。它通过链接使用唯一状态来源，切题时归档任务记录。mpmath #922 已验证同一题内的状态读取与评分，具体见[实验记录](../../experiments/chainswe-baseline/state-maintenance-pilot.md)。
3. 下一步在同一线路下按顺序逐题运行 mpmath 四题链，对照纯 Pi、A4 和 StateSystem。重点记录任务切换后更新是否到达 Agent、是否被用在行动中，以及读取、诊断和额度中断带来的开销。模型调用须遵守项目授权。

状态组织、数据结构和机制选择保持开放。自动标记失效、证据范围表达、独立验收和行动提醒是候选手段。DSH 提供机制与案例参考，LongHorizon-Harness 提供分离执行与验证的先例。旧 [Change Graph 设计](../../history/design/change-graph-task-state/)供追溯和比较，旧任务状态架构与接续安排已退出主线。
