# 项目语义状态管理：规格研究入口

现行[研究意图](../intention/intention.md)明确了研究对象、手段、目的与设计倾向。当前没有已批准的正式 Specification Package；本文组织待收敛的系统行为与设计材料，不构成实现交接。

## 待转化为规格的研究要求

系统应赋予 Agent 维护和查询项目语义状态的能力，支持知识积累与开发相互促进。LLM 承担信息价值、抽象、关系和有效性的语义判断；系统提供组织、持久化、关系、查询、证据与验证能力。具体工具、调用时机、约束强度和外部辅助仍需比较。

后续规格需明确状态与实际项目的关联、更新与失效行为、查询的任务范围、证据及权威性表达，以及出现冲突或无法验证时如何处理。形式完整和引用存在不能等同于语义正确。

实验需同时研究有效性与可靠性：原生 Agent 的能力、工具的增量、状态质量，以及计入维护成本后的开发正确率与效率。状态漂移、错误复用、过时依据及维护成本超过收益可作为失败线索；具体指标、对照与判定阈值尚未锁定。连续接续可作场景，不是唯一验收方式。

## 未决设计

状态表示、组织与权威来源、维护和验证策略、查询与投影、工具边界、Benchmark 及成本口径尚待确定。Event Sourcing 和 Change Graph 均为候选思想；五类对象、双视图界面和可靠性模块不是预先锁定的系统结构。

后续先以学术与工程材料形成问题证据，再确定具体行为、不变量、失败处理与可执行实验协议；正式规格与架构取舍需据此审查。
