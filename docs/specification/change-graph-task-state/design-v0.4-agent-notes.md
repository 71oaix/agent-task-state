
# 架构设计 v0.4：Agent 接手与查证约束

主阅读入口为[架构设计 v0.4](design-v0.4.md)。沿用[v0.3 接手说明](../../../history/design/design-v0.3-agent-notes.md)的保存、来源和授权边界，本文补充2026-10-12用户确认的历史图与详情接口。旧版内容保留；尚未实现界面或数据接口。

## 新的设计要求

历史图是 Human View 的主入口，总览只呈现有意义的工作和关键变化。详情分为证据核查、决策核查和执行清单，显示图对应版本的记录；不能靠模型事后猜测补足缺失资料。

证伪入口必须指向具体判断、证据版本和判定记录。观察与解释分开，证据范围不够时只能显示尚未确认，不能将局部失败扩大为整条路线证伪。

决策入口关联提议者、实际决策或批准主体、执行者及指令来源，缺失身份标为未知。Agent执行某条用户指令不能登记为Agent自行决定；反过来，不得把Agent自己的建议冒充用户批准。组织优先级与技术证据分别呈现。

执行清单与 Change、任务及文档版本关联，支持多对多。不把执行步骤当成历史图默认节点。SDD规格、issue、plan和验收记录采用原项目状态口径，文档存在不等于获批，步骤完成不等于验证或验收通过。恢复工作时保留清单修订历史及未完成事项。

界面查证和后续 Agent 读取应访问同一批版本化记录，不能维护两套不同真相。这里规定语义接口和阅读行为，不提前选择HTTP路由、数据库、图组件或SDD执行器。

## 后续验证

正常路径包括展开工作修订、点证据定位实际结果、点决策定位发出者及依据、点执行清单查看版本和未完成项，查看历史后返回原图位置。

边界包括来源缺失、证据已过期、判断尚未确认、清单过期或未批准，以及一个计划覆盖多项工作。图与详情必须对应同一任务状态版本；不同版本需明确标注，不能静默拼接。

2026-10-12用户确认了图作为人类主入口，并要求证据、决策主体及执行清单可查看；该确认不自动批准全部数据模型、实现或实验。技能操作记录采用本说明与Git，不改全局skill和记忆。
