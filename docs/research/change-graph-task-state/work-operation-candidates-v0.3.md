# 工作操作候选 v0.3：共同版本底座与七个语义入口

**当前保留七个语义接口候选，底层优先共用版本登记与检查规则。**十一项组合、十二项待补证保持前轮去向；三十项名称新增和删除均为零。本页替代 v0.2，成为唯一现行候选清单。[本轮依据](transition-rule-review.md)给出 T14、T12、T02 的完整转换，主结论从[工程全景](dsh-work-history.md)阅读。

本轮的进展是接口效果具体化：open 创建可跟踪工作初版，close 修订指定尝试的处置，select 只改变一个范围的采用。统一 record 可以承载相同效果，但必须保留这些类型约束。已有目标和成果初始登记、相关变化成组也计入底座。open/close 优先检验为便利封装；最终分类等待独立使用结果。

## 七个语义入口分别改变什么

| 接口 | 作用 | 需要保留的规则 | 来源见证 |
|---|---|---|---|
| `open` | 开启一次可独立跟踪的工作 | 工作身份、目标归属与初始责任；历史创建时间可未知 | [T14.03](dsh-process-truth-v1.md#t14) |
| `revise` | 修订同一对象的成果 | 前版、改变与保留范围；产生后继，采用另记 | [T01.02](dsh-process-truth-v1.md#t01)、[T01.03](dsh-process-truth-v1.md#t01)、[T01.04](dsh-process-truth-v1.md#t01) |
| `close` | 收束指定工作尝试 | 停止推进、处置与后继；父目标状态独立 | [T14.03](dsh-process-truth-v1.md#t14) |
| `observe` | 留下可查的观察 | 对象、方法、结果、时间与报告归属；观察与解释分别保存 | [T13.02](dsh-process-truth-v1.md#t13)、[T13.03](dsh-process-truth-v1.md#t13)、[T13.04](dsh-process-truth-v1.md#t13) |
| `judge` | 形成或修正判断 | 证据、前提、适用范围与取代的旧判断 | [T13.01](dsh-process-truth-v1.md#t13)、[T13.02](dsh-process-truth-v1.md#t13)、[T13.03](dsh-process-truth-v1.md#t13) |
| `select` | 改变一个范围内的采用 | 原采用、新采用、决定及冲突；持有旧版的范围另存 | [T09.02](dsh-process-truth-v1.md#t09)、[T13.04](dsh-process-truth-v1.md#t13) |
| `bind` | 绑定有明确含义的联系 | 如使用契约、分配责任、证据支持；端点、版本与范围固定 | [T13.05](dsh-process-truth-v1.md#t13)、[T12.03](dsh-process-truth-v1.md#t12) |

身份分配与继续同一工作的判断由调用者声明并留依据。接口处理记录及其一致性；来源报告、研究归纳、实际执行分别归属。已有观察与工件版本继续可查，当前采用按具体范围解释。

## 十一项组合设计

下表记录工作含义的展开。步骤由证据决定：原因未知可没有 judge，未报告采用可没有 select，检查未进行可保留待检查。原始来源缺少的动作不自动补齐。

| 动作 | 操作组合 | 必须保留的含义 | 依据 |
|---|---|---|---|
| `split` | 开启子工作 → 绑定分配责任 → 修订父项残余 | 分配前责任、子范围、重叠/未决、父判据与一致逻辑组 | [T12.03](dsh-process-truth-v1.md#t12)、[T12.05](dsh-process-truth-v1.md#t12)、[T03.06](dsh-process-truth-v1.md#t03) |
| `review` | 观察被评审对象 → 形成评审判断 | 评审对象、评审角色、依据、适用范围；不改变采用 | [T11.03](dsh-process-truth-v1.md#t11)、[T09.02](dsh-process-truth-v1.md#t09) |
| `decide` | 记录理由和意图 → 按实际效果组合采用、收束、开启或修订 | 意图与已报告效果分开；按来源决定可选步骤 | [T14.03](dsh-process-truth-v1.md#t14)、[T04.02](dsh-process-truth-v1.md#t04) |
| `verify` | 观察检查方法与结果 → 按明确判据给结论 | 对象版本、方法、判据、未覆盖范围和报告者；接受另记 | [T12.06](dsh-process-truth-v1.md#t12)、[T13.04](dsh-process-truth-v1.md#t13)、[T14.04](dsh-process-truth-v1.md#t14)、[T15.05](dsh-process-truth-v1.md#t15) |
| `revert` | 有理由时保存判断 → 修订撤回/保留范围 → 有采用依据时更新采用 | 局部撤回、后续独立修补、未知原因均保留 | [T01.02](dsh-process-truth-v1.md#t01)、[T01.03](dsh-process-truth-v1.md#t01)、[T03.02](dsh-process-truth-v1.md#t03)、[T12.02](dsh-process-truth-v1.md#t12) |
| `adapt` | 绑定变化后的契约 → 修订消费者 → 有检查结果时留观察 | 兼容判断及取用范围由调用者提供；未见证步骤留缺口 | [T01.04](dsh-process-truth-v1.md#t01)、[T01.05](dsh-process-truth-v1.md#t01)、[T14.02](dsh-process-truth-v1.md#t14)、[T14.04](dsh-process-truth-v1.md#t14) |
| `repair` | 观察故障 → 有依据时修正判断 → 修订成果 → 记录检查或再失败 | 保留旧解释、失败修补及新证据；不补造每一步 | [T10.03](dsh-process-truth-v1.md#t10)、[T10.04](dsh-process-truth-v1.md#t10)、[T10.05](dsh-process-truth-v1.md#t10)、[T13.01](dsh-process-truth-v1.md#t13)、[T13.04](dsh-process-truth-v1.md#t13) |
| `replace` | 修订组成 → 绑定新使用关系 → 有采用依据时更新采用 | 旧新范围与兼容/历史去向；名单任务等独立部分保留 | [T04.02](dsh-process-truth-v1.md#t04)、[T04.04](dsh-process-truth-v1.md#t04)、[T04.05](dsh-process-truth-v1.md#t04)、[T05.04](dsh-process-truth-v1.md#t05) |
| `retire` | 修订可用范围 → 调整新选择 → 保留仍有效的持有或接口联系 | 提供者退出、旧运行修订退役和工作收束分别限定对象 | [T07.03](dsh-process-truth-v1.md#t07)、[T07.04](dsh-process-truth-v1.md#t07)、[T02.04](dsh-process-truth-v1.md#t02) |
| `integrate` | 绑定来源及取用范围 → 修订目标 → 记录变化后的前提与检查 | 捕获侧可复用，旧外发承诺不自动继承；代码取用范围未知另记 | [X1](work-operation-rounds-v0.1-evidence.md#补查来源) |
| `release` | 观察发布报告或实际结果 → 绑定包、版本及渠道依据 → 有渠道变化时更新采用 | tag、发布成功、渠道采用分开；未知回执不得补造 | [X2](work-operation-rounds-v0.1-evidence.md#补查来源) |

## 本轮取舍与下一步

**名称去向维持 7 / 11 / 12；实现角色已明确为共同底座上的语义入口。**逐项删除时，七入口均可改写为有类型的版本登记；留下的必要信息包括身份和责任、观察归属、判断依据、采用范围、有类型关系及其版本。两方案的区别在检查规则的组织位置。[逐项替代与代价](transition-rule-review.md#两种机制的实际差别)

split 在 T12 展开为开启子工作、分配责任、修订父残余，须成组检查责任去向。T14 的 adapt/rewrite 只登记来源报告支持的契约和实现，不补造代码取用。T02 的保留与清理先记录为设计规则，不创建来源未提供的运行实例。

离线原型规格采用 record(expected, changes, basis, provenance, group) 承载统一检查，七入口编译到相同变化；先用三案例和错误输入检查状态、拒绝原因与证据追踪。[规格与启动条件](transition-rule-review.md#离线原型规格与启动条件)

当前已经完成主作者的来源走查和声明一致性核对。Qoder MCP 已按用户要求移除；原三并发输入保留，独立构造、读回和使用成本比较另行安排。底座选择是本轮原型建议，易用性优势由后续独立任务检验。
