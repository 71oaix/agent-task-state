# Change Graph 任务状态直接近邻核验

## 当前阅读说明

2026-10-14：当前研究目标为寻找能组合出复杂工作管理能力的基本对象和操作，见[元操作候选 v0.2](primitive-candidates-v0.2.md)。下文预算视图及旧判断适用性优先的推荐均为已撤回的历史判断，文献事实保留；最新十项方法映射见[协议与近邻对照](primitive-candidates-v0.2-agent-notes.md)。不能把 ESAA 简化成只有 append，或因 MAGE 没有名为 select 的接口就断言不能切换路线。当前没有证明候选表达能力严格更强。

## 历史判断

**2026-10-10 纠偏：暂不推荐将题目收窄为预算受限视图。** 首轮审查列出了机制重叠，却没有充分审查作者为什么保留这些信息、消融是否支持这些选择、实验能否代表持续演化的开发工作。预算视图是助手提出的历史候选，不是用户已经选定的研究方向。以下原判断保留为过程记录；该句属于当时的判断；现行方向以本文开头的阅读说明为准。

当前设计的大部分基础机制已有直接先例。不能把“状态独立于 Context”“执行图或树”“保留失败分支”“有效状态替换旧状态”单独包装为新贡献。值得继续检查的是：当既有状态大于工作预算、部分证据因意图或环境变化失效时，如何生成支持下一步行动的视图，决定复用、取回与重新验证，而不是只解决记忆问答。

这只是候选问题，并非已证明的空白。下面是限定于所核验版本与章节的覆盖判断；没有对整个领域完成穷尽性检索。来源身份、venue、日期与阅读深度统一见[来源清单](source-inventory.md#2026-10-09-首轮核验记录)，本报告不登记另一套发表状态。所有工作均未经本项目复现。

同名排除：多供应商路由的 ContinuityBench（arXiv:2607.15899）及其他同名 GitHub 项目不是本轮引用的恢复论文。不能将它们的仓库当作 Gulati 论文代码。

ContinuityBench 的 h1 是 structured summary，h2 增加准确动作历史；它已经研究“更多历史不一定更好”。因此动态 View 必须对照它的结构摘要，而不是只对照空 Context。

InterruptBench 的多轮文档明确：通过 Stage 0/1/2 的多次 run + replay 链接更新，run.py 本身一次处理一个 interrupt；不能把文档名称解读为一个运行里已实现任意次数原生中断。

## 候选空间与否决条件

候选：**当前有效状态无法整体装入预算时，行动所需证据如何被选取、复用或重新验证？**

需要同时考虑：当前意图、下一步义务、依赖变化、证据作用范围、已实现环境效果和取证代价。这些元素分别已有先例；可能的贡献在于一个可区分的在线选择策略或适用条件发现，不能来自概念拼装。

与[手工示例](traceable-example.md)的关键衔接是：修改数量可以保留同月完整排序，修改月份需要新证据；导航进度可以保留。这个小任务用普通状态表就能解释，因此它是“不要过度设计”的校准例，不是图方法胜出的证据。

下一关：先在公开任务中找到真实、足以超过简单状态表/固定视图能力的前缀，冻结原始证据与环境状态；没有这种实例就不进入大系统实现。问题与公平对照具体见[研究问题卡](problem-card.md)。

## 2026-10-10：保留信息的理由与实验证据

研究顺序改为先审查论文的问题证据、信息选择理由、消融与任务代表性，再选择研究问题及验证任务。故事用于解释已发现的困难，不替代困难存在、机制必要或方法有效的证据。task 0 只可作为约束替换的诊断小例，不能代表复杂开发，也不能据此断定真实工作用简单状态表就足够。

### MAGE：执行依赖和错误隔离有依据，图的独立贡献尚未隔离

作者认为语义检索会割裂相互依赖的决策，也可能混合有效与错误轨迹。因此保存原始动作与观察、子目标摘要、当前路径以及其他分支的提示；Maintain 校验摘要与轨迹，Revise 隔离错误段。这里信息选择有明确的失败机制，不能只理解成“多存一点历史”。依据为 [v1 §1–3](https://arxiv.org/html/2606.06090v1)。

§4.4 表4分别去掉 Compress、Maintain、Revise，在购物与旅行任务上成功率均下降。这支持这些操作在该协议中的作用，但并未逐项移除每类记录，也没有在完全相同信息与预算下单独隔离树结构相对平面表示的贡献。整套系统获益不能自动证明每个字段或图本身必需。

MemoryArena 有跨步骤约束和较长行动链，比单次查询修订更适合检验执行依赖；但所核验实验没有专门检验多个仍有价值的技术方向并行探索、因组织优先级暂停、随后重新启用。MAGE 的错误隔离有用，不等于其结果已经验证这种开发生命周期。

### StateMem：更新效力比信息新旧更关键，依赖传播有反例

作者保留来源、优先级与替代关系，是为了区分仍有效的事实和被替代的事实；anti-trap 测试还要求拒绝无权改变状态的后续提及。因此“最近出现就覆盖旧值”并不充分。依赖标记则为派生结论随条件变化后的重算服务。依据为 [v1 §4–6](https://arxiv.org/html/2608.19652v1)。

§6.2 表3中，DeepSeek-V4-Flash 的 extraction-only 为0.174，加入 supersession 后为0.298，完整方案为0.363；去掉依赖传播反而为0.373。Qwen 的完整方案为0.233，去掉传播为0.222。作者指出传播可能误伤 anti-trap，并报告每配置单次运行。因此不能把依赖传播当作稳定成立的优势，更不能由此要求所有工作关系都自动联动失效。

StateMemBench 的合成状态变化与陷阱筛选适合隔离“知道旧事实却沿用错误状态”的问题，不代表真实开发中这些困难的自然频率。其生成规则与方法设计同源，作者也将对应收益视为上界，并用 LongMemEval、LoCoMo 检查泛化；这些仍主要是问答评测，不能直接替代在线开发决策与执行结果。

### InfiAgent：文件状态支持长期完成，但覆盖率不等于开发路线管理

thinking record 保存待办、相关文件、持续保留的规则或失败经验、后续工具步骤，意在窗口重置后仍能继续工作。§5.2 的80篇本地 PDF 任务检验是否真正读到正文并产出基于内容的非空笔记，文件状态的消融支持长期覆盖能力；该指标不直接评价每份总结质量，也没有逐项证明所有记录项必要。依据为 [正式论文 §3.3、§4.2、§5.2](https://aclanthology.org/2026.findings-acl.1787.pdf)。

§4.2 的层级 Agent 采用有明确边界的串行调用，不能因出现“多 Agent”就视为已覆盖多个竞争技术路线并行研究。长期文献任务有其代表性，但其代表的是持续执行与覆盖，并非技术债、MVP 生长及组织决策反复切换。

### 对本项目的实际影响

用户提出的 A/B/C 说明，未被选中、被暂停和被证伪具有不同含义；选中方案仍可能带有技术债、未决假设与局部可用成果。回到 A 时还要判断其证据和实现是否适用于已经变化的现状，不能整体恢复旧世界。这些是研究必须尊重的工作语义，不是已经证明的图结构需求。

接下来继续审查现有论文怎样界定工作对象、如何观测失败、对照是否隔离信息本身的作用，以及任务覆盖哪些生命周期。基于已观察困难再选公开开发任务与评分方式。现有实验没有专门覆盖某现象，只能说明当前证据范围不足，不能直接据此宣布领域空白、构造新 benchmark 或确定论文题目。

## 2026-10-13：第一轮广搜后对直接近邻的修正

当前研究判断见[第一轮结论](research-round-1.md)，详细章节与固定静态资产见[证据说明](research-round-1-evidence.md)，官方身份统一见[source-inventory R1–R16](source-inventory.md)。本次核对日期2026-10-13，未运行实验。

ESAA（R1，2026，venue待核实）是新增的重要直接近邻。意图/执行分离、追加事件、程序验证、投影与精简读状态均已被其讨论。三组件职责划分和状态外置不能独立承担论文新意；案例主要支持可行性，不支持条件更新或收益归因。它的任务终态与可修订工程结论应分开比较，不能凭“任务done不可改”断言我们的问题已经解决或肯定没解决。

EMG（R7，所读v1，2026，venue待核实）说明把失败转成有效消息已有结构比较路径。其成功轨迹参照、非软件环境和未充分隔离图结构收益，限制向复杂开发的直接迁移。SWE-ContextBench（R5，v1，2026，venue待核实）的Oracle/自由检索和轨迹/摘要对照，要求把信息选择与表示分开；不要笼统说保存更多历史有益。TMS（R11，1979期刊）把前提、依据与信念修订的经典邻域引入比较，全文操作仍待精读。

原有 MAGE、StateMem 等近邻继续保留。以下收窄推荐已撤回，保留历史记录：当时将候选增量收窄为变化条件下旧工作判断的适用性维护，但没有确认新颖性；须与其实际修订操作和强文档对照逐项比较。SWE-Milestone（R10，ICML2026主会）优先用于连续任务材料诊断；SCBench（R2，v2，2026，venue待核实）用于自己的代码设计如何影响后续扩展。任务依赖图不等于尝试/决策演化图，复杂任务失败也不能都归于记忆丢失。
