## 执行范围与可信度

完成相关广搜及重点章节核查，没有做完整系统综述。检索围绕 continuous software evolution / long-horizon coding / iterative requirements / context compaction / experience reuse / event sourcing agents / truth maintenance / execution provenance 展开，并沿软件演化基准的比较表、ESAA、经验记忆与追踪综述扩展。不是仅检索 Change Graph。广搜后将文献归为连续执行、经验复用、上下文管理、语义更新、软件演化评测、多 Agent 组织与来源追踪。

## 对方法与实验证据的具体判断

### ESAA：必须认真比较的直接近邻

§3 将意图与实际状态写入分开，事件记录和状态投影可重建；程序校验、精简读视图与我们三组件职责重叠。§5 诊所案例 50 任务，结束时 31 完成，其余仍 ready/backlog；run success 不能等同于任务全完成。§7 将结果定位为可行性。没有强对照支撑因果收益，也没有充分验证改变前提后的旧工程结论管理。

论文§3.2 与§4.2 列出的“事件追加/文件效果”顺序有文字张力，需代码审计才能判断事务语义，不据此断言实现有漏洞。固定仓库投影规范含任务 review、审批、issue/hotfix；不能把较新 README 能力都视为 v1 论文已验证。任务完成的终态约束，也不等于所有工程判断永久有效。

### 软件演化任务：不要混合不同连续性

SWE-Milestone v4：阶段依赖由提交重组、运行校验及人工检查建立；运行中持续代码及会话，完成阶段后快照评估。§5.5 按测试状态构造传播链，其原因归类另用 LLM 比较规格、代码和 gold patch。传播统计和模型审阅都不是完整语义因果证明。§5.6 观察压缩后的探索上升，也观察可控的 Context 波形；附录 C 的边界放错、宽泛抑制错误等案例提示竞争解释。原始历史以已实现路径为主，文档提交被过滤，不能代表被放弃的方案全集。PMLR 证明 ICML 主会发表，v4 的具体内容未逐页与正式 PDF 对照。

SCBench v2：36 问题 196 阶段；v1 的 20/93 不能混用。§2.2 每阶段新会话、保留代码；§2.4 分别检查新能力与累积回归，代码复杂性/重复性是质量代理，不是完整维护性。公开 code_search/config 与第一阶段规格已固定获取，附录核对阶段 1 至 3 逐渐扩展功能。不是实际路线失败证据。当前任务仓库已分离；不要按旧 README 位置准备运行。

SWE-ContextBench v1 在隔离环境生成经验，再到相关任务显式检索；不是同一项目持续继承代码。自由/Oracle、完整轨迹/摘要的对照有价值：正确选择摘要有收益，自由检索不保证。§3.3 resolved 口径主要按 F2P，P2P 另列，不能把其成功率当成“所有回归通过”。相关任务由 PR/issue 联系构造，需检查同 PR 重叠及时间顺序；当前仓库数据数量与 v1 不同，不能混算。

## 下一步执行单元：先查真实材料，再做离线表示

1. 查询 SWE-Milestone 官方数据及轨迹发布入口。检查一个真实仓库连续片段是否含任务、代码快照、工具结果、压缩事件、许可与评分对应关系。记录可用/缺失项及获取成本；不把论文图当可回放轨迹。
2. 获取 SCBench code_search 连续阶段的完整规格和评分协议，只在研究侧核实后续变化；被评估接手者只能看到截至断点已公开内容。研究侧知道未来不等于 Agent 输入可泄露未来。
3. 选择确有条件变化、结论依据和可恢复产物的片段。若没有暂停/恢复，明确覆盖缺口；合成事件另列压力测试，不称真实开发史。私有 Pi 聊天不用作实验。
4. 使用共同事实制作强文档与显式版本关系两份表示。先手工检查表达能力、更新动作和证据定位，不调用付费模型。至少检验目标、方案状态、旧结论范围、受影响项与最小回查对象；只根据当时材料评分，允许未知、争议和多个合理行动。
5. 给出一个最小操作清单及失败条件，随后才起草语义模型。没有解释不了的真实操作，就不新增对象。词义约束、依赖更新和 LLM 判断准确性分开；TMS 全文及近邻具体更新操作优先精读。

通过标准不是“画出来很清楚”：表示须能在不补写事实的情况下支持查证和更新，强文档不能轻易达到同样维护效果，否则收敛为简单文档/索引方案。离线通过不等于论文效果成立；后续小原型及端到端实验仍按 v1.0 gate 执行，付费与实现权限不由本轮报告扩大。
