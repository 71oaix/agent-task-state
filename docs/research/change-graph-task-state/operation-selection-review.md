# 工作元操作筛选：逐步更新与候选裁定

本轮直接检验：接手者面对新信息时，哪些操作帮助它准确更新工作，哪些可以由组合承担。起点为[候选 v0.3](work-operation-candidates-v0.3.md)，当前七项不预设赢家。执行中的结果与最终裁定在本页维护，主阅读入口为[工程全景](dsh-work-history.md)。

## 结果与处置

独立执行者自行更新后，观察/判断和工作生命周期两组均可用共同入口保留关键含义。关系在责任拆分中可内嵌，采用可由有效决定日志恢复。四入口组合已实际重放；本轮据此给出[候选 v0.4](work-operation-candidates-v0.4.md)。

| 比较 | 实际结果 | 处置 |
|---|---|---|
| observe / judge 与有类型陈述 | T14 与 T13 均保留来源、解释和历史；校准误拒绝来自检查器过宽 scope 约束 | 合并为 statement，保留类型规则 |
| open / close 与创建/修订 | T14 接续、T03 多阶段未完均可恢复，父目标未被关闭 | open/close 移出独立核心，作为组合/便利接口 |
| 独立 bind 与内嵌关系 | T12 独立校准通过；T01/T07 主 Agent 走查可保留范围、来源和责任 | 默认内嵌有类型引用；独立关系身份按需 |
| select 与有效决定日志 | 两种方案都保住 T14 当前采用；T04/T08 本地走查分别保存消费者范围 | select 保留工作入口，日志为强替代，显式计算其恢复规则 |

四入口不是函数数量下界：实际删除变换后，三入口与两入口也可重放相同效果，对象类型和规则仍然存在。继续数函数名称无法进一步筛选机制；下一阶段比较应针对这些规则是否必要、是否使接续更可靠。

## 本轮证据怎样分层

- 独立执行：四组校准、Windows 判断修正和迁移接续，共 36 次逐步更新。校准 72 个语义检查项由另一独立审阅者评分；跨过程陈述/生命周期 36 项由主 Agent 核对实际保存状态与来源。
- 本地走查：关系与采用的跨过程剩余 12 次更新由主 Agent 完成，另目录保存，不计入独立执行。X2/C 在额度错误前已保存完整输出，主 Agent 核对文件后应用；X3/A、B 因额度错误未产生提案，不记为语义失败。
- 实际程序检验：18 项单元测试、八案例组合重放和四/三/两入口删除变换；旧资料和当前冻结代码指纹分别核对。
- 成本：账户用量触顶后停止全部重试；遵照用户要求停止默认三并发。没有用量回执的 token/费用标未知。起止时间包含编排等待，不能作为人工维护时间。

## 冻结的比较办法

每组只改变一种机制，其余入口与信息要求相同。A 使用独立入口，B 使用替代表达，C 维护普通工作文档。三个执行者使用新的独立上下文；先给当前记录和第一条新信息，提交后才释放下一条信息。

| 组 | A | B | 校准材料 | 冻结后复查 |
|---|---|---|---|---|
| 陈述 | observe / judge | 同一 statement 入口，保留观察/判断类型 | T14 | T13 |
| 生命周期 | open / close | create / amend 工作对象，保留生命周期约束 | T14 | T03 |
| 关系 | 独立 bind | 对象内有类型的精确引用 | T12 | T01、T07 |
| 采用 | 独立 select | 带范围与依据的 decision | T14 | T04、T08 |

T14/T12 的回顾快照采用受控拆分，属于更新任务设计，不充当历史真实发生时刻。T13、T03 等按已知来源版本或提交顺序组织；无法建立先后的来源保留未知。固定资料截至 2026-10-15。

评分先核对工作含义与来源，再检查更新一致性，最后比较规则、调用者判断、修正和查证负担。允许不同的正确对象划分；不按标准操作序列或字面字段计分。每步三个语义检查项在执行前固定，答案同时核对实际保存的记录。

每步最多一次结构错误修正，首次输出保留。校准后每组最多一轮规则修订，再冻结用于跨过程检查。来源缺失、表示遗漏、规则歧义、编码错误与读回错误分别裁定。独立执行者只允许读取自己的输入和先前记录；上下文和分包隔离不等同本机文件物理隔离。

## 检查器负责什么

[离线检查器](../../../tools/work-operation-checks/README.md)已实现 apply、replay、export，使用 Python 标准库。它检查准确前态、对象类型、明确变化、精确引用、作用范围、责任分配和成组更新。结构合法的工程判断仍需来源核对；普通文字不被程序当作事实证明。

共同实现只用于应用参与者独立提交的更新和检查规则。两套人工预编码表示的效果相等，不作为本轮筛选证据。语义评分读取完整状态与历史，不使用省去来源/版本的便捷投影代替完整记录。

本轮代码验证命令：在仓库根目录运行 `python -m unittest discover -s Agent任务状态管理/tools/work-operation-checks -v`。已保存正常应用和拒绝过期更新的实际输出；后续运行保留首次结果。

## 校准发现与规则冻结

陈述组曾发生一次实现误拒绝：普通判断范围的修订被套用关系/采用的 scope 不可变约束。已缩小约束作用对象，保留首次拒绝和修正，归因为检查器问题。采用组在派发前明确改为真正的追加有效决定日志，由 supersedes 链恢复采用并显式暴露分叉；未使用仅改接口名称的别名作为替代。

检查器新增决定链的精确前驱、同 scope、循环与分叉检查，当前 17 项单元测试通过。freeze-v2.json 固定代码、契约与评分材料指纹，跨过程阶段不边测边补规则。独立校准审阅包含逐项字段/文段依据，保存于本批 review/calibration/；评分表示信息满足程度，不代表接口优越性。

## 组合重放、剩余过程与可复现入口

combined-replay.json 保存选中替代的实际命令组合和状态；deletion-profiles.json 保存四/三/两入口变换。每次均应用检查器并保留准确引用，输出与所选记录的语义投影一致；这是组合回归，不是新一次独立使用。完整状态和历史继续保存，投影只用于对齐结构别名。

其余 T02/T05/T06/T09/T10/T11/T15/T16 的变化按既有来源作影响核对，记录在 remaining8-impact.json；不当作八次独立重编码。设计与运行实例、产品授权与开发授权、实施与验收、源代际与目标格式继续分开。

重现程序检查使用工具 README 命令；研究原始目录先复制到新批次再执行脚本，不覆盖已有结果。runner 拒绝覆盖已存在输出；修正仅跟在首次拒绝之后，原提案保留。C1/B 第2步修正前答案未单独快照，首次提案和拒绝输出保留、最终修正答案用于评分；后续运行已修正快照捕获。
