# 工作操作候选 v0.5：基本入口、组合功能与执行规则

**四个基本入口保持不变，本轮把八个组合做成可执行功能。**使用者可以描述部分撤回、责任拆分、接续重做等变化，查看其展开、结果和准确版本。接口是否继续细分，由使用中的具体困难决定。

| 基本入口 | 稳定效果 |
|---|---|
| create | 建立一个对象的身份和首版；同名已有对象拒绝重建 |
| revise | 基于准确前版产生后继，未改内容保留，旧版可查 |
| statement | 保存有归属的观察或判断；来源报告、研究判断和实际验收分别表达 |
| select | 改变指定范围采用的准确版本；其他范围和旧持有关系继续存在 |

## 工作功能怎样组合

| 可执行组合 | 展开与保证 | 主要见证 |
|---|---|---|
| 部分撤回 partial_revert | 明确已知部分的退出/保留 → revise；漏交代或范围重叠时拒绝 | Loader局部撤回 |
| 替换组成 replace_parts | 明确退出/保留/新增 → revise；旧版保存退出前内容 | Creator、E2B与接口 |
| 责任拆分 split | create 子工作 → revise 父分配；未分配和重叠显式保留，父项不自动完成 | 聊天分项推进 |
| 接续重做 rework | create 新尝试 → revise 旧尝试关闭；引用原目标与历史参考 | 消息反馈 UI 重做 |
| 收束尝试 close | revise 工作的处置与关闭；目标状态不受自动传播 | 迁移撤回、Loader尝试退出 |
| 范围引用 reuse | 固定成果版本与取用范围 → revise 类型化关系 | SSH公共接口、插件管理、Office引擎 |
| 采用版本 adopt | 固定准确版本 → select；作用范围不变 | 预设、各消费者的设计选择 |
| 修正判断 correct | statement 新判断 → 引用旧解释与新证据；旧陈述继续可查 | Windows终端排查 |

修补可以组合“登记故障报告 → 修正解释 → 修订成果 → 登记检查报告”；适配可以组合“引用新契约 → 修订消费者 → 登记检查报告”。来源没有给出的步骤保持未知。组合执行器按提交的动作展开，不自行生成工程判断。

## 对象与更新规则

目标保存工作的意图；尝试保存本次推进与处置；成果/契约保存可复用内容；陈述保存有归属的信息；采用保存范围内的选择。关系可附在对象版本中，跨工作或需要独立引用的关系使用对象身份。研究者补建的目标、尝试和责任标签均标明研究归属。

记录修订号、产品发布版本、Git版本和运行修订分别保存。T02的旧运行修订属于声明式架构内的寿命规则，不能指向更早的旧架构来替代未知的具体版本。采用范围包含所属工作域，决定说明与采用对象分别具有身份。

每次准备更新固定读写前版与引用版本，执行时重新检查；历史引用可以故意指向旧版。一个组合及其来源登记在步骤内共同成功，失败返回步骤前状态。回执保留每条基本操作与对象变化，可仅用保存的事务恢复任一局部步骤。

语义核对给出一条具体规则：**未知继续留在原来的位置。**T12尚不清楚六项细分责任分别由哪个子项承接时，父项保留这些残余，子项先登记已知范围。T14只报告决定重做时，新尝试的实施起点仍未知。未分配责任不等于功能未完成，验收unknown不等于尚未验收。来源没有作出这类判断时，不额外生成待办。程序负责前态、引用与责任约束，来源审阅负责这些工程分类是否成立。

## 候选变化与下一步

本轮基本候选新增0、移除0，仍为 C03 revise、C12 select、C31 create、C32 statement。八个执行组合是已有组合候选的实现或便利名称：partial_revert对应C17，replace_parts对应C23，split对应C05，rework组合C01/C07及接续关系，close对应C07，reuse对应C21及C06的取用部分，adopt是C12的调用接口，correct使用C32及判断修订关系。修补、适配等继续通过组合表达。

全部32个历史编号沿用，4核心候选/14组合与便利/2合并/12待补证。下表沿用此前裁定，新增可执行范围以上表为准。

|---|---|---|---|
| C01 | `open` | 作为组合动作（便利接口） | create(kind=work)；来源身份、初始责任与实际开启时间分别保存 |
| C02 | `propose` | 待补证 | 当前主要是 proposed 状态与 PR 范围；首次提议事件、后续处置尚未展开。 |
| C03 | `revise` | 保留为核心候选 | 修订既有记录，准确前版、显式变化、后继与未改字段；初版另由 C31 创建 |
| C04 | `fork` | 待补证 | 分支存在不足以说明两条独立工作路线的共同起点；需适当见证。 |
| C05 | `split` | 作为组合动作 | 开启子工作 → 绑定分配责任 → 修订父项残余；分配前责任、子范围、重叠/未决、父判据与一致逻辑组 |
| C06 | `integrate` | 作为组合动作 | 绑定来源及取用范围 → 修订目标 → 记录变化后的前提与检查；捕获侧可复用，旧外发承诺不自动继承；代码取用范围未知另记 |

| C09 | `review` | 作为组合动作 | 观察被评审对象 → 形成评审判断；评审对象、评审角色、依据、适用范围；不改变采用 |
| C10 | `judge` | 合并到 C32 | statement(type=judgment)，保留结论、前提、证据、范围与被修正判断 |
| C11 | `decide` | 作为组合动作 | 记录理由和意图 → 按实际效果组合采用、收束、开启或修订；意图与已报告效果分开；按来源决定可选步骤 |
| C12 | `select` | 保留为核心候选 | 显式更新有范围的当前采用；决定日志可替代，但带来前序与冲突恢复规则 |
| C13 | `implement` | 待补证 | 实施尝试、实际产出与失败之间的映射不完整，撤销机械 observe+revise 展开。 |
| C14 | `land` | 待补证 | 需指定集成目标与合入效果；合入、采用、验收分别记录，撤销固定三步展开。 |
| C15 | `verify` | 作为组合动作 | 观察检查方法与结果 → 按明确判据给结论；对象版本、方法、判据、未覆盖范围和报告者；接受另记 |
| C16 | `accept` | 待补证 | 缺有权主体依据判据接受结果的事件。 |
| C17 | `revert` | 作为组合动作 | 有理由时保存判断 → 修订撤回/保留范围 → 有采用依据时更新采用；局部撤回、后续独立修补、未知原因均保留 |
| C18 | `adapt` | 作为组合动作 | 绑定变化后的契约 → 修订消费者 → 有检查结果时留观察；兼容判断及取用范围由调用者提供；未见证步骤留缺口 |
| C19 | `repair` | 作为组合动作 | 观察故障 → 有依据时修正判断 → 修订成果 → 记录检查或再失败；保留旧解释、失败修补及新证据；不补造每一步 |
| C20 | `migrate` | 待补证 | 主要见证迁移契约；实际实例、拒绝结果与产出映射尚缺。 |
| C21 | `bind` | 作为组合动作（布局可选） | 有类型关系可存于 owner.links 并由 create/revise 写入；需要独立引用时再给关系身份 |
| C22 | `release` | 作为组合动作 | 观察发布报告或实际结果 → 绑定包、版本及渠道依据 → 有渠道变化时更新采用；tag、发布成功、渠道采用分开；未知回执不得补造 |

| C24 | `retire` | 作为组合动作 | 修订可用范围 → 调整新选择 → 保留仍有效的持有或接口联系；提供者退出、旧运行修订退役和工作收束分别限定对象 |
| C25 | `constrain` | 待补证 | 多为常设规则；规则的制定、修订和生效事件尚未厘清。 |
