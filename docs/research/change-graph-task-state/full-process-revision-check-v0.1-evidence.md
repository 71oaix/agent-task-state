# 十六段连续过程的修订规则检验：证据与裁定

人类结论统一维护在[修订应该承担什么](revision-composition-experiment-v0.1.md)。本页负责本轮协议、逐段裁定、读回问题及失败；2026-10-22 的 12 条款实验保留在[前轮明细](revision-composition-experiment-v0.1-evidence.md)。

## 固定输入与执行

以[过程底稿 v1](dsh-process-truth-v1.md)的 16 段、83 条事实及已有 68 步表示为输入，检验同一套 R0 修订规则。R0 要求同一明确对象、精确基版本和预期当前版本、改变与保留范围；产生新版本，历史保留。修订不代替兼容性判断、实施、验证或采用。其他操作沿用待归约候选，不能偷偷减少其数量。

主仓库根目录相对路径 `artifacts/agent-task-state/maintenance/dsh-full-process-check-2026-10-22/` 是本轮唯一批次：10 月 22 日固定材料，10 月 23 日完成派单与裁定。输入和原始模型输出保留本地，保持忽略。`freeze.json` 固定规则、事实、表示、问题与主 Agent 初稿；收尾核对哈希不变。源码及冻结底稿不修改。

- `prepare.py` / `representations.json`：按 68 步保存事件、来源、改变与保留范围、理由、跨过程联系及状态。所有身份为研究声明，不假造上游工作 API。
- `reader-input.json` / `answer-key.json`：每段五问，共 80 问：当前与未完、原因及未知、撤回与保留、关系类型、验证范围。问题及初始答案提前固定。若答案键也复制了错误分类，评分注明修正，而不把它当金标准。
- `review-input.json`：规则路与反例路收到同一批事实和表示；读回路只有表示与问题。原输入复制进各自 `lanes/` 工作目录，副本哈希一致；读回目录无评分答案。它仍是输入分离，不声称建立了严格安全隔离。
- 中断前未出现新任务。恢复后检查任务列表再派单，未重复运行前一批；三项新任务均完成且无权限拒绝。主 Agent 来源审查在读取三路新结论前另存 `main-source-audit.json`。

实际使用了 implement、judge、select、revise、observe、bind、land、propose、followup、split、verify、close、open 共 13 种候选。规则名单漏列 propose 和 verify，已计入额外候选。fork 与 integrate 列为候选但本批未形成调用见证。68 步均仍以自然语言承载部分工程含义；因此本轮没有把它们登记为已完成归约的操作契约。

## 定向补查与审查者错误

模型挑战具体影响结论后，只复核已有固定版本的四份原文，记录在 `targeted-source-check.json`。本轮不扩展全链接队列。

| 固定来源 | 所问问题 | 核对结果与后果 |
|---|---|---|
| S028 聊天架构 | “回退”只是性能退化，还是实际撤回？| 原文明确 PR 合并八分钟后 reverted；保留撤回事实，驳回反例路没有撤回的说法 |
| S036 Creator | 持久化限制就是改方案的理由吗？| Problem 明确同对话安装使用与第二套插件生命周期；用原文理由修正冻结表示中过度简化的因果 |
| S004 Schedule | 冷会话与 Host 存储是否真有因果？| Problem 及 Decision 明确冷会话、无需激活即可查任务；保留理由，但与后来裁剪理由分别绑定 |
| S034 子代理 | 无额外完成通知与接受重复通知是否冲突？| workflow 使用 caller delivery；模型工具使用 parent delivery。是消费者范围不同，不能硬判来源矛盾 |

跨过程关系另对照固定底稿“跨过程联系”表。审查输入只有 83 事实正文及表示，未完整供应该表，导致反例路将多条已有整理依据的联系判为共享术语臆测。主 Agent 保留来源支持的使用、持有、共享语义和格式契约；不扩成具体组件同一性、同一 payload 或开发因果。后续独立审查应一并提供关系证据，而不是只给事实段落。

规则路声称删除不是修订、旧版本保留就意味着旧代码继续运行，这两项不采纳。以仓库为对象，移除提供者就是后继版本；历史与当前采用必须分开。相应地，也不从提供者退役或组件职责边界补造工作 close/split 事件。反例路将自然语言因果判断都标为可程序验证也不采纳：程序只能检查调用者给出的结构化依据，不能凭字段存在确定依据的真实性。

T01 的机械中间态检查、T11 的输出游标来自前批补读，不在本轮 83 事实正文里。其历史记录保留，本轮单列额外查证需求，未算来源内验证通过。T02 早期问题与后次声明式改造之间的具体因果仍未知。

## 补充边界探针

`boundary_probes.py` 在来源审查及读回之后提出 8 项声明矛盾检查：未知代码前驱、无依据因果、运行契约错作工作收束、迁移契约错作执行、子项未完却父目标完成、接纳错作模型完成、仍有持有者却覆盖旧版本、抹除已有实现报告。8 项均被显式规则拒绝，4 个合法对照被接受。

另有一个反例被接受：调用者把没有来源支持的因果标成 `causal_evidence=true`。它说明程序检查的上限在于声明一致性；错误语义标注仍需查证。探针是构造记录，不是 DSH 实际事故、源码执行或预注册实验，也不证明 8 条规则各自必须成为基本操作。
