# 研究计划 v0.1：执行与证据说明

人类审阅以[研究计划](research-plan-v0.1.md)为准。本文件负责后续执行，不向用户转嫁普通核验。2026-10-12新增计划，未实现原型、未产生模型实验结果；沿用独立研究工作树，旧设计保留。

## 来源和阅读顺序

以下官方页面于2026-10-12检索或打开；此次是计划所需的入口与适配风险审查，不是全文精读或复现。正式研究须将论文具体章节、代码固定版本、发表身份与消融局限写回 source-inventory 和 neighbor-review，不能凭这里宣布机制成立。

1. [JJ operation log](https://docs.jj-vcs.dev/latest/operation-log/)：软件官方文档，无学术 venue。配合已登记的 Change 身份和演化文档；动手探索需使用一次性测试仓库，保留操作前后记录。
2. [Event Sourcing](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)：Microsoft 官方架构文档，无论文发表身份。学习事件历史与状态重建，以及事件版本演化的代价；不是采用该模式的充分理由。
3. [PROV Primer](https://www.w3.org/TR/prov-primer/)：W3C 2013 工作组 Note；与 PROV-DM 推荐标准身份区分。学习实体、活动、主体、使用和派生关系，不必照搬本体。
4. [Skyframe](https://bazel.build/reference/skyframe)：Bazel 官方文档。学习依赖记录、失效与增量重算；工程依赖可计算不代表语义推论可确定重算。
5. [Zep](https://arxiv.org/abs/2501.13956)：2025 arXiv 论文入口，本轮未确认正式发表 venue；不能断言未发表。后续检查时间事实、失效、检索、评测与源码一致性。
6. [ATIF RFC](https://github.com/harbor-framework/harbor/blob/main/rfcs/0001-trajectory-format.md)：Harbor 官方工程 RFC，页面标注2026年4月、v1.8；非学术论文。当前为可变 main 页面，采用前固定 commit 和 schema，检查工具调用、结果、子轨迹及用量引用。
7. [SWE-EVO 论文入口](https://arxiv.org/abs/2512.18470)与[官方仓库](https://github.com/SWE-EVO/SWE-EVO)：2025 arXiv 初始记录，正式发表身份待核实；本轮阅读摘要和仓库说明，未查完整实例或运行。候选执行底座，不声称有我们所需的在线干预协议。
8. MAGE、InfiAgent、StateMem、CAT、SKILL.state、CFRC、InterruptBench 的官方入口及前次核验见[source-inventory](source-inventory.md)，信息选择和消融局限见[neighbor-review](neighbor-review.md)。此前记录不可当成此次重新核验。ContinuityBench 的直接获取限制仍保留。

用户笔记中的 ESAA、AgentOps、From Agent Traces to Trust、Experience Memory Graph 尚需核对精确身份，未据此建立设计结论。不为了凑六篇补写论文内容。

## 操作顺序与交付边界

A. 机制审查：先 JJ / PROV / 事件与投影，随后依赖变化与 Agent 近邻。每项提炼场景、记录、更新操作、证据、缺口和采用决定。只扩展能回答未决问题的文献，避免无界阅读。

B. 材料筛选：先静态检查候选任务许可证、环境、依赖、评分、真实历史可见性和未来信息泄漏；登记接受和拒绝理由。3个探索、2个保留案例只是初步工作量，缺乏可用案例时报告缺口，不降低复杂性条件。个人 Pi 对话不进入实验、checkpoint 或统计；另一项目任务和授权不继承。

C. 表示检验：人工核对的事实层与模型推导层分开。状态需区分未探索、探索中、暂缓、未采用、失败结论及其条件。更新考虑并发旧版本、重复提交、冲突证据、缺失依据、执行清单和技术债。引用能指到具体版本；未知保持未知。

D. 原型提案：对象和更新操作经过保留案例检查后，提出单一能力切片的实施范围。没有 ready 规格不直接开发；计划请求不自动批准安装环境、付费运行或大规模采集。

E. 先导实验协议：冻结数据划分、模型版本、工具、上下文限制、压缩规则、资源上限、对照实现、评分与失败计账，提交具体预算后才运行付费调用。标准断点包含环境状态和外部效果记录，文本前缀不等于可恢复环境。共享前缀的生成策略也要披露，避免只选择有利轨迹。

F. 正式验证：按项目或任务聚合结果和不确定性；每个压缩次数层报告暴露量。主终点为独立验收的最终需求满足，过程指标解释原因。报告基础任务能力不足导致的失败，不把所有错误算为记忆失败。不能依赖实验后人工修补工作库而仍称全自动。

## 不同证据支持什么

程序不变量测试支持存储与更新规则；人工标注支持有限案例的语义判断；固定断点对照支持局部恢复效果；端到端长程执行支持累积维护效果；人类对照支持理解和查证效果。这几类证据不能相互替代。

整体系统对比之后，优先消融初步显示有贡献的机制。去图对照保留相同事实、版本与可访问材料，明确移除的是关系遍历或关系驱动更新，不删掉对手的信息。动态视图对照保持状态相同。人工正确状态只做上限诊断。近邻适配必须标明改动，不能冒充官方复现成绩。
