# 十六段调研之后：候选找到了什么，下一步比较什么

**16 段已经逐段分析完。原来的六个候选不够，还需要表达“得到证据、作出判断、决定采用、实施和验证”等变化。**我们先把这些补入候选池，再检验哪些能组合、哪些可以合并。

最有说明力的是终端排查：先判断故障来自提示符晚到，等待修补无效；新探查发现尾部格式被改写，于是修改解释并更换控制台。只记最终代码，就会丢掉失败尝试和改方案的依据。[查看这段推演](work-operation-coverage-v0.1-evidence.md#t13)。

另一个区别来自聊天返工：整批功能回退后，独立功能与分组工作分开推进。基础实现已有进展，产品和性能验收仍待完成。因此“拆分工作、提交成果、通过检查、完成目标”需要分别表达。[查看这段推演](work-operation-coverage-v0.1-evidence.md#t12)。

**本报告提出的后续比较已完成一轮：[查看实验结论](revision-composition-experiment-v0.1.md)。以下保留比较起点。**

**当时的问题：改错、适配新接口、撤回旧改动，能否共用一种“生成新版本”的操作？**

| 实际做的事 | 新版本相对旧版改变了什么 |
|---|---|
| 修补缺陷 | 改掉有问题的实现 |
| 适配新接口 | 修改消费者，使它符合新的接口约定 |
| 撤回旧改动 | 移除指定变化，保留其他成果 |

它们都产生新版本，但需要的步骤可能不同。我们会各取一段真实过程写出步骤，再尝试用同一组操作表达。合并以后，读者仍应能回答：改了哪里，为什么改，旧成果还剩什么。答不清的地方，就是需要补规则或保留独立操作的地方。

目前整理了 30 项待比较的候选，其中有重叠项，也有尚缺真实见证的项。分叉、开发工作暂停和恢复仍需补证。本轮覆盖的是固定的 16 段材料；最终元操作集尚未确定。
