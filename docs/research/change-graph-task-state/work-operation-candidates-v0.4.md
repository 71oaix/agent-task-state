# 工作操作候选 v0.4：四个工作入口与组合规则

本页保存2026-10-25的筛选依据；现行可执行规则见[v0.5](work-operation-candidates-v0.5.md)。

**下一原型采用 create、revise、statement、select 四个工作入口。**open/close 作为组合与便利接口，observe/judge 合并为有类型陈述；关系默认作为版本内容中的精确引用保存。当前四入口是可复验的工程基线，初始登记、对象规则和组合约定全部计入。[主结论](dsh-work-history.md)解释取舍，[实验明细](operation-selection-review.md)给出来源、实际更新与裁定。

| 入口 | 改变什么 | 必须保留的规则 |
|---|---|---|
| create | 创建一个对象的初始描述版本 | 身份已知不存在、类型与来源归属；研究登记时间与历史创建时间分开 |
| revise | 产生同一对象的后继描述 | 准确前态、显式变化、未改字段、旧版可查；相关变化成组 |
| statement | 登记有归属的观察或判断 | type 区分；观察保留对象/结果，判断保留结论/证据/范围；已有陈述可由 revise 修订 |
| select | 改变指定范围的当前采用 | 原采用/新采用、准确版本、范围、效力依据与冲突；其他持有者不随之改写 |

关系用有含义的 relation、from/to 精确端点与 scope 表达。简单关系可以进入 owner.links；版本演化保存旧关系。把关系作为独立对象时，其稳定身份、引用与修订也要明确登记，当前不强制增加该层。

## 本轮发生了哪些变化

新增两个清单名称：C31 create 将原先隐含的初始登记计入；C32 statement 接替 observe/judge。旧编号全部保留，没有删除历史记录。独立核心竞争由七项变为四项；当前共 32 项：4 核心候选、14 组合动作（含便利接口）、2 已合并、12 待补证。

- **观察/判断：**observe、judge 合并为 statement；用 type 区分观察和判断。相同入口保留来源、结论、证据、适用范围与旧判断；独立函数未产生本轮必要区别。
- **生命周期：**open、close 移出独立核心，作为 create/revise 的组合与便利接口。首次尝试、后继、目标延续和阶段未完均可恢复；关闭只修订尝试处置，不传播父项完成。
- **关系：**bind 默认展开为 create/revise 中的有类型精确引用；独立关系对象按需。T12 分配、T01 保留与消费者责任、T07 接口保留可在 owner.links 中保存。
- **采用：**select 保留为当前工作入口；有效决定日志保留为强替代。追加日志可恢复同一采用，但需要前序、生效、同 scope 与分叉解析；直接更新有范围的采用当前更便于明确回执。

## 采用范围与下一步

四入口组合已用同一检查器跨八个更新案例重放。进一步把 statement 改写为 create(kind=statement)、把 select 改写为 revise(adoption)，两入口版本同样保留记录效果。因此本轮选择的是工作接口，尚不能据函数数量宣称最小元操作；有类型对象、前提、范围和效力规则都是机制的一部分。两入口方案保留为强对照。

本轮到此结束筛选。下一阶段复用现有检查器与已选入口，同前驱选择的冲突测试已存在；只在真实需要独立引用/修订关系时补反例，再验证按版本查证与恢复工作视图；不重新枚举三十个名称。长期任务的工具使用与压缩后接续收益留给后续 SWE-Milestone 阶段。

证据范围：四组校准及陈述/生命周期跨过程由独立执行者更新；关系/采用跨过程因用户成本指示与额度限制改为主 Agent 走查。源语义评分与机械检查分别记录，未测得维护时间或模型成本优势。以后默认主 Agent 加本地脚本，只有影响候选裁定的必要争议才调用一次小范围独立审阅。
