# DSH 真实开发过程底稿 v0.1

这份底稿固定十条真实过程，供后续不同记录方法使用同一个输入。它不采用任何候选元操作，也不以某套操作能表达什么来删改材料。每一步的编号只用于查证，不预设数据对象。

**本版的 truth 是公开证据可支持的过程，不是项目全部活动的全知记录。**Git 合入、版本中存在的文档、作者报告的故障和理由分别标明。没有独立重跑工程；记录中的性能和测试结果不能升级为本研究已验证结果。材料截止2026-10-15固定提交，整理于2026-10-19。精确来源、旧版本正文及缺口见[证据底稿](dsh-truth-v0.1-evidence.md)。

阅读下面每条过程，可以直接看到前后变化、保留范围和当前结果。某些起点仅由后来的设计记录回顾，已明确写出；无法确定的因果和时间保持未知。十条过程之间不强行串成单一时间线。

## T01 · 插件加载：加入事务重载，后来选择性撤回

**T01.01**　8月2日有一个提交加入事务式配置重载。 [L1](dsh-truth-v0.1-evidence.md#t01)

**T01.02**　后来的决定要求撤回 #932 的五个提交；它记录的理由是候选导入、回滚和生命周期处理使 vendored 实现偏离上游过多。 [L2](dsh-truth-v0.1-evidence.md#t01)

**T01.03**　撤回范围不包括较大合并中的无关仓库插件能力；初始文件读写和模块导出相关的两项修补继续保留。 [L2](dsh-truth-v0.1-evidence.md#t01)

**T01.04**　9月9日出现撤回提交及消费者适配提交，9月11日又有保持启动失败策略的修补。 [L3 L4 L5](dsh-truth-v0.1-evidence.md#t01)

**T01.05**　截止快照记录的结果是：插件失败可以留下部分应用的配置树，Loader 不自动恢复旧配置；需要可用插件的消费者自行审查实际激活结果。 [L2](dsh-truth-v0.1-evidence.md#t01)

**缺口：**未取得完整 #932/#936 审阅讨论及最终决策者。 没有独立重跑修补保留、启动失败或回滚测试。

## T02 · Agent 预设：按会话装载，改为声明式配置并保留旧修订

**T02.01**　rc.7 的记录说明，先前进程级配置决定全部会话能力；当时已改为每个 Agent 装载自己的预设目录，Host 的注册服务和跨会话设施仍共享。 [P1](dsh-truth-v0.1-evidence.md#t02)

**T02.02**　同一份历史记录记下了实施中的问题：Host 读者曾找不到移入会话的服务，卸载可能改写预设输入，存储后端没有全部保存新增预设身份，Host 缺少闲置 Agent 的释放时机。 [P1](dsh-truth-v0.1-evidence.md#t02)

**T02.03**　9月21日主线有声明式预设提交；在 0.1.7-rc.2 中，预设已由普通配置声明，注册器拥有运行修订及其插件树。 [P4 P2](dsh-truth-v0.1-evidence.md#t02)

**T02.04**　修改定义会使旧修订退役；正在使用它的 Agent、子代理和临时读取者继续持有引用，最后释放时才清理。配置持久化与实际激活结果分别报告。 [P2](dsh-truth-v0.1-evidence.md#t02)

**T02.05**　旧可执行修订只保存在进程内；重启按保存的预设身份解析当前配置，缺少定义时拒绝恢复。因此记录没有承诺跨重启还原旧可执行修订。 [P2 P3](dsh-truth-v0.1-evidence.md#t02)

**缺口：**没有恢复全部局部修补各自进入主线的日期。 配置记录和作者测量没有独立运行复验。

## T03 · 会话迁移：一次合入与撤回，之后再引入流式实现

**T03.01**　8月25日主线合入 #2698，提交正文将其称为流式格式迁移管线。 [M1](dsh-truth-v0.1-evidence.md#t03)

**T03.02**　同日主线合入 #3054，正文为撤回该迁移管线。现有这些提交元数据没有给出撤回的工程理由。 [M2](dsh-truth-v0.1-evidence.md#t03)

**T03.03**　9月6日主线合入 #3585，属于后来的流式迁移实现。两个实现是否相同、后者具体复用了前者多少，尚未核实。 [M3](dsh-truth-v0.1-evidence.md#t03)

**T03.04**　截止快照的设计记录报告，一份116 MB会话在整份转换实现中耗尽16 GB Node进程；这是作者记录的失败，不是本研究重现的测量，也没有证据将它作为8月撤回原因。 [M4](dsh-truth-v0.1-evidence.md#t03)

**T03.05**　截止记录采用每份会话独立的有状态转换阶段；原已提交格式文件保留，仅发布最终当前代际，中间格式不逐份落盘。不同历史代际的解释和拒绝规则分别保留。 [M4](dsh-truth-v0.1-evidence.md#t03)

**T03.06**　同一截止快照里，LogicalSession 存储重建仍是 proposed：阶段1、2写为draft work complete，阶段3记录实现与远程CI完成但仍draft，阶段4、5未完成。不能因流式迁移存在就将该提案整体记为已完成。 [M5](dsh-truth-v0.1-evidence.md#t03)

**缺口：**第一次撤回原因未知。 未审计两个迁移实现的完整diff和代码复用范围。 作者性能数字未复测。

## T04 · Team 消息：从独立 outbox 改为目标 inbox，保留名单与任务

**T04.01**　0.1.7-rc.2 的 Team 记录将发送意图先写入并刷盘到 Lead 日志，再向目标投递并确认；恢复时重试未确认项，并提供目标侧去重。名单和共享任务也有各自的持久状态。 [T1](dsh-truth-v0.1-evidence.md#t04)

**T04.02**　新记录把独立 outbox 的身份、确认、重试和清理视为重复管理，选择直接通过目标 Agent inbox 接纳消息。 [T2](dsh-truth-v0.1-evidence.md#t04)

**T04.03**　该变更10月8日合入主线；0.2.1-alpha.2中已有对应记录。9月26日是笔记名中的日期，不能代替主线合入时间。 [T3 T2](dsh-truth-v0.1-evidence.md#t04)

**T04.04**　新发送返回接纳的消息身份或失败；Team 不另行保存未接纳意图、不负责重启重试、不对显式重发去重；接纳也不证明模型已经处理。 [T2](dsh-truth-v0.1-evidence.md#t04)

**T04.05**　旧 mailbox 记录仍可解码和展示，但旧待发项不再投递；替代范围仅为消息机制，成员名单和任务决定继续保留。 [T2](dsh-truth-v0.1-evidence.md#t04)

**T04.06**　记录明确以实验功能无稳定性承诺作为取舍条件，并承认失去旧消息恢复能力的后果。 [T2](dsh-truth-v0.1-evidence.md#t04)

**缺口：**未取得实际用户待发消息损失的数量。 未独立执行新旧消息恢复测试。

## T05 · Creator：临时修改运行时，转为安装持久插件

**T05.01**　rc.8 的旧工具允许模型检查、临时装载和卸载进程内插件；临时插件不写文件，不修改配置，重启后不恢复。 [C1](dsh-truth-v0.1-evidence.md#t05)

**T05.02**　旧记录要求保留实验成果时另行实现普通项目插件或可安装 bundle，没有自动转正路径。 [C1](dsh-truth-v0.1-evidence.md#t05)

**T05.03**　9月16日 #4324 合入主线；0.1.6-alpha.2记录Creator改走已有插件管理器：先写包和配置文件，再安装bundle。 [C3 C2](dsh-truth-v0.1-evidence.md#t05)

**T05.04**　模型侧旧的生成代码修改入口退出，但已有运行时和Client消费者继续保留所用服务；历史工具卡片仍可读取。 [C2](dsh-truth-v0.1-evidence.md#t05)

**T05.05**　新安装的配置跨重启保留并影响同一profile中的会话；工具操作要求完整访问或单次批准，配置保存与能力实际生效分别报告，已安装包替换当时需要重启。 [C2](dsh-truth-v0.1-evidence.md#t05)

**缺口：**未逐个审计中间工具名称和全部生成代码工作流修订。 没有把一次批准误记为永久提升会话权限。

## T06 · 定时任务：从会话日志转为Host存储，再限制历史保留

**T06.01**　0.1.7-rc.1 的提醒以原会话日志为唯一持久依据，只在会话活跃时运行；冷会话不触发，重新加载后再处理过期提醒，分叉不继承父任务的活跃执行。 [S1](dsh-truth-v0.1-evidence.md#t06)

**T06.02**　0.1.7-rc.2 已记录改用独立Host任务存储，恢复计时器不必先加载全部会话；到期时再恢复原会话并投递。作者记录的目标包含独立查看待处理和已投递任务。 [S2](dsh-truth-v0.1-evidence.md#t06)

**T06.03**　历史schedule事件仍可读，但不自动导入新任务存储；加载有旧活跃提醒的会话会提示重建。规则中部分旧时间计算和接纳语义继续适用。 [S2](dsh-truth-v0.1-evidence.md#t06)

**T06.04**　同一Host存储记录后来保留任务和回执；专门的后续决定记下了全量JSON重写下的增长问题，改为删除任务时删除其行与回执，并按时间和数量限制交付历史。 [S2 S3](dsh-truth-v0.1-evidence.md#t06)

**T06.05**　被裁剪的历史标注已移除，旧记录本来就没有历史则标注不可用，二者不混同；删除任务不会删除已经进入会话的消息。 [S3 S2](dsh-truth-v0.1-evidence.md#t06)

**T06.06**　回执证明消息已持久进入inbox，不证明模型完成；任务存储与消息存储不共享事务，记录明确保留崩溃重复风险。 [S2](dsh-truth-v0.1-evidence.md#t06)

**缺口：**Host存储和裁剪决定都已在rc.2中，不能用这两个发布快照确定两者之间的部署间隔。 没有实际跨库崩溃注入或用户升级复验。

## T07 · 远程执行：移除E2B实现，保留接口并继续SSH路线

**T07.01**　8月8日主线合入E2B概念验证相关分支；后来的退出记录说明，它曾为文件、进程、终端等提供同一个远程执行世界。 [R3 R1](dsh-truth-v0.1-evidence.md#t07)

**T07.02**　退出记录说明，新PTC需要与程序标准流独立的双向控制流；当时固定E2B SDK的通道能力及输出保留使继续适配需要额外传输工程。 [R1](dsh-truth-v0.1-evidence.md#t07)

**T07.03**　9月11日主线合入移除E2B提供者的变更；截止记录列出实现、SDK依赖、集成夹具及可选工作流等移除范围。 [R4 R1](dsh-truth-v0.1-evidence.md#t07)

**T07.04**　通用文件系统、进程和终端接口及其异步语义继续保留；远程执行需求没有取消，记录也没有断言E2B原则上无法支持。 [R1](dsh-truth-v0.1-evidence.md#t07)

**T07.05**　截止SSH记录由远端helper提供执行能力，Harness、凭据、模型传输与会话持久化仍在本地；断连后的修改性操作不自动重放。 [R2](dsh-truth-v0.1-evidence.md#t07)

**缺口：**未核实SSH引入与E2B删除每个提交之间的依赖及精确先后。 不把两个供应实现画成未经证实的单一直接替换提交。

## T08 · 子代理：先分开持续会话与一次执行，再统一activation入口

**T08.01**　0.2.1-alpha.1 的持续子代理记录回顾了先前Task结束就销毁Agent的办法，并指出它把会话生命周期与一次结果绑定在一起。 [A1](dsh-truth-v0.1-evidence.md#t08)

**T08.02**　该版已将持久Session与进程内Activation分开：同一会话可多轮续接、冷恢复，Agent inbox负责消息顺序；一次性提供者执行路径仍独立存在。 [A1](dsh-truth-v0.1-evidence.md#t08)

**T08.03**　10月6日统一子代理重构合入主线；alpha.2记录将所有提供者接入统一activation入口，本地spawn/fork只提供创建数据。 [A3 A2](dsh-truth-v0.1-evidence.md#t08)

**T08.04**　模型委派返回后台子任务身份；工作流通过同一activation等待结果并清理，不额外给父Agent发送完成通知。 [A2](dsh-truth-v0.1-evidence.md#t08)

**T08.05**　外部后端保留一次执行能力，没有因此获得多轮续接或本地Session；统一的是容量和生命周期管理。执行结果可在清理失败时保留，清理错误另行报告。 [A2](dsh-truth-v0.1-evidence.md#t08)

**T08.06**　历史一次执行描述仍可读取；新执行路径移除不意味着删除旧会话数据。完成通知可能与子代理主动汇报重复，这是记录明确接受的代价。 [A2](dsh-truth-v0.1-evidence.md#t08)

**缺口：**没有把早期Task方案的回顾当作已经取回当时每个执行步骤。 未独立运行取消、后代等待或外部提供者测试。

## T09 · 侧栏：从工具详情到通用工作区，调整布局和内容的寿命

**T09.01**　0.1.5-alpha.1 记录旧右栏只能显示工具详情；文件链接交给Host操作系统，远程浏览器无法直接查看文件。 [U1](dsh-truth-v0.1-evidence.md#t09)

**T09.02**　同一记录保留了方案试验：评估第三方布局库，保留FlexLayout作备选；自建原型通过相关浏览器检查后继续自建。这里只能认定为作者报告的检查。 [U1](dsh-truth-v0.1-evidence.md#t09)

**T09.03**　记录中的首个原型采用drawer；产品形态改为实际挤占聊天宽度的右侧栏，布局支持分栏、标签、浮窗及撤销，内容类型由另外的插件接口提供。 [U1](dsh-truth-v0.1-evidence.md#t09)

**T09.04**　后续记录指出，卸载内容或改变其DOM祖先会断开浏览器页面；侧栏为声明keepMounted的类型提供内容保留，Desktop Browser启用它，其他类型仍按可见性挂载。停靠、浮动和会话切换不移动已保留页面的DOM祖先。 [U2](dsh-truth-v0.1-evidence.md#t09)

**T09.05**　布局状态、内容实例寿命和数据读取分别承担责任；后续保留内容树的决定没有整体废弃侧栏布局引擎。 [U1 U2](dsh-truth-v0.1-evidence.md#t09)

**缺口：**试验中的完整原型、每次用户评审和失败录像未取回。 布局库评估与浏览器通过均未独立复测。

## T10 · 目标控制：保存目标，再修复人工暂停被执行绕过的问题

**T10.01**　早期goal记录将目标修改写成独立goal/change事件，下一轮提示另由驱动组件入队；目标存在不以消息是否被模型接纳为条件。 [G1](dsh-truth-v0.1-evidence.md#t10)

**T10.02**　持久目标与进程内运行授权分开；恢复或分叉可保留active目标，但默认disarmed，不会因打开会话就自动继续。 [G4](dsh-truth-v0.1-evidence.md#t10)

**T10.03**　第一次暂停修复记录的问题是：Web已标记paused并禁止后续自动轮次，但当前模型轮仍在执行，还可能自行调用resume。修复增加人工暂停时取消当前轮，并保留输入队列。 [G2](dsh-truth-v0.1-evidence.md#t10)

**T10.04**　后续记录指出，前一个修复后，稍后的人类轮次仍可能被模型用来恢复持久paused目标；UI也混淆了active-but-disarmed与armed。 [G3](dsh-truth-v0.1-evidence.md#t10)

**T10.05**　后续改动禁止模型工具恢复持久paused目标，仍允许它在合适人类输入下恢复active-but-disarmed或blocked目标；界面分别显示运行授权，人类显式恢复入口继续保留。 [G3](dsh-truth-v0.1-evidence.md#t10)

**缺口：**前后暂停修复的完整运行故障日志未取得。 文件名日期只作主题标识，不作为此处精确合入日期。

## 本版如何继续修订

本底稿是后续重建对照的权威文本，修订时保留旧版。原始证据、已知事实、未知项分开；新证据可以纠正事实，但不能为某套编码方便而修改原过程。未来重建不能把这些十条过程的原始正文、证据底稿或事实清单同时交给重建者，否则会泄漏答案。

本版没有声称穷尽DSH，也没有为这十条过程恢复所有中间提交。已保存所选主题在40个版本点的所有目录映射与不同正文；逐步事实仍以本页明确列出的证据范围为限。下一步先查证有争议的事实与关键缺口，再冻结某一版输入并比较记录方案。没有进入元操作编码或反向重建实验。
