# Intention Brief：软件开发历史的最小语义层

## 目标

已有工作大多已经把 Agent 的状态和工作轨迹保存下来。本项目不把「任务状态离开模型上下文」当作贡献。

要做的是在已有状态与轨迹之上，建立一个更小的抽象语义层：用少量可维护对象和可组合操作，把会分叉、回退、局部改版的软件工作记录成可查询的历史与现状，再从同一套记录生长出两套视图：

- **Human view**：让人直观把握当前进度与依据。
- **Agent view**：让 Agent 理解任务现状、减少跑偏。

这层语义要成立，必须证明它比「保存轨迹或普通工作文档」多出可检验的约束。例如：计划改版后，旧成果仍指向旧计划；尝试结束，目标仍可待验收；依据可按范围纠正，旧报告仍然保留。若做不到，它只是另一种整理方式，还不能称为更好的范式。最终要用可对照的证据支撑一篇论文，而不是先建成完整系统再去寻找有效性。

## 使用场景

- 长周期软件开发中，目标、计划、尝试、成果与依据会分叉、回退、局部改版；聊天 Context 装不下或被清空后仍需接续。
- 人类需要一条可读的进度与证据路径，而不是原始轨迹堆。
- Agent 需要一份可查询的现状摘要与证据入口，而不是重读全部历史。

## 参与者

- 研究者（设计维护对象、记录规则与视图）。
- 人类开发者 / 审阅者（消费 Human view）。
- 执行软件任务的 Agent（消费 Agent view，并在接续时写入新进展）。

## 期望结果

1. 从近邻如何保存状态与轨迹出发，收敛出一组足以描述软件开发历史的维护对象，以及可由它们组合出的常见工作变化，而不是为每种表面活动各造一条原语。
2. 该语义层能完整、可接续地记录对象身份、版本、变化与出处。
3. 同一套记录可投影出 Human view 与 Agent view。
4. 用可对照的证据表明：有该语义层时，Agent 对任务现状的理解与接续质量优于仅有轨迹或普通工作文档（或明确失败边界），并足以支撑一句讲得清的论文主张。

## 约束和假设

- 近邻工作已覆盖「状态出 Context」、执行图或树、保留失败分支、有效状态替换旧状态等表层叙事。贡献必须落在语义层多出来的约束，以及它如何帮助接续，不能再包装这些已有机制。
- 表示完备和离线记录自洽，不等于论文主张成立。不要用持续更新对象规则、扩大检查器来代替决定性对照。
- 先把「这层语义比轨迹多什么」写清楚，再做一次真实接续；视图是同一记录的生长物，不是另一套互不相干的日志。
- 付费实验与部分外部核验当前未授权；验证路径需在现有约束内设计。
- DSH 等外部仓库是验证材料和灵感来源，不是本项目的主线工作。

## 非目标

- 不做通用聊天记忆产品，也不追求覆盖所有 Agent 框架的轨迹交换格式。
- 不把「字段越多越好」或无限细化本体当作成功。
- 不在 Intention / 规格未锁前，用更多对象修订代替决定性接续实验。
- 暂不把已暂停的「预算下证据视图选择」当作当前主线（可作后续问题，不混进本轮成功标准）。

## 当前歧义

- 五类对象（目标 / 计划 / 尝试 / 成果 / 依据）是否最小，仍开放。
- 「优良的最小操作」的可失败标准尚未钉死（何时停止生长操作集）。
- 论文的自变量、因变量与失败长相尚未写成可执行实验协议；主张句也尚未写下。
- Human / Agent 双视图尚未接到同一套日常使用入口。

## 成功标准

- 语义层能覆盖选定软件开发历史案例中的关键变化，且新增真实操作优先由组合得到，而非常规加原语。
- 同一记录可投影出对人类可读、对 Agent 可执行的现状视图。
- 至少一次**真实 Agent 小任务接续**（Context 受限或清空）表明：沿用计划版本并保留旧成果、报告与验收依据时，该语义层比普通文档或原始轨迹有可观察的好处；或清晰记录失败并反推对象/视图缺口。
- 上述证据足以支撑一篇论文的核心主张表述（主张句可一句话讲清）。
