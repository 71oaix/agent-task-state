# 已有记录工作的整理与分析

这份整理只看本项目已经写下的自有记录：活动调查、操作组合与筛选、T12 对象研究，以及离线检查器。判断标尺与现行 [Intention](intention.md) 一致：已有工作多半在保存状态和轨迹；要问的是，后来收敛出的维护对象和规则，是否已经形成一层比轨迹或普通文档更强的语义，还是仍停在记录器自洽。DSH 过程编码和历史地图是外部材料上的作业，不在此当作自有贡献展开。

## 活动调查：普通文档已经能支持当时的查证

依据 [`experiments/activity-survey/activity-record-agent-mapping.md`](../../experiments/activity-survey/activity-record-agent-mapping.md)（已归档）。2026-10-15 把软件开发归纳为十二类活动，并在六个有材料边界的工作点做了表示走查和删除检查。

当时的结论写得很清楚：需要持久保存的是会影响后续工作的含义及其依据，不能把每次工具输出都升级成一项工作；认真维护的普通工作文档已经能够支持当前的问题查证，还没有证据证明图或某个元操作能让接手更快。走查是同一人读过完整材料后的表示检查，不是盲测，也没有测时代价或模型效果。

对现在的语义层来说，这是一条负向校准，不是失败后的废案。任何「更好的范式」都必须先越过这道对照：若普通文档已经答得清，结构本身不能被写成收益。

## 操作组合：修订不能混用，函数个数也证明不了最小

依据 [`revision-composition-experiment-v0.1.md`](../../experiments/operation-composition/revision-composition-experiment-v0.1.md)、[`operation-selection-review.md`](../../experiments/operation-composition/operation-selection-review.md)、[`work-operation-candidates-v0.5.md`](../../experiments/operation-composition/work-operation-candidates-v0.5.md)（均已归档）。

把同一套规则放回全部 16 段过程后，关键发现是：若只写「前版变成后版」，会把不同的延续关系混在一起。例如关闭旧全栈分支、按既有后端重写 UI，不能只连成旧 UI 的下一版；计划或定义更新后，旧运行版本仍可在各自范围有效；修订转换规则与执行一次迁移是不同事件。接手读回也曾把「后端刚落地时功能未完」「后续 UI 实现」和「没有独立验收」混成同一类剩余事项。结论是：保留「修订」来表达明确对象内的成果变化；尝试身份、责任拆分和对结果的认识必须分开。

筛选阶段把工作入口收敛到四个记录层接口：`create`、`revise`、`statement`、`select`，并用它们组合部分撤回、责任拆分、接续重做等变化。同时写明：四入口不是函数数量下界；删除变换后，三入口与两入口也可重放相同记录效果。继续数函数名称无法进一步筛选机制。v0.5 因此把四入口留作记录层接口，把可靠性问题转给对象与连续变化检验，并写「先观察接手时真正缺了什么，再调整对象和操作」。

这一段已经摸到语义层该分的东西：对象身份、版本范围、尝试与成果不是同一种「下一版」。它还没有证明这些区分能让真实 Agent 接续更好。

## T12：五类对象是当前实现选择，不是已验证的最小范式

依据 [`experiments/t12-objects/t12-object-study.md`](../../experiments/t12-objects/t12-object-study.md)（已归档）。推荐把记录拆成目标、计划、尝试、成果、依据，用 Change 保存每次变化的前后状态与出处。它要拆开的，正是容易被压成一个状态的进展：目标可以继续，尝试可以结束；计划可以改版，旧成果仍指旧版；成果可以只推进或撤回一部分；依据可以纠正一条命题而不删旧报告。

存放对照里，独立存放被推荐，依据是引用和生命周期，不是行为对照上的唯一必然：依据并入 Change、目标与尝试合并，「未发现行为差异」。十五段静态回查写 77 条事实都可放入五类加 Change，没有段落要求第六类；这只说明覆盖得下已整理材料，不能说明五类已经最小。T12.01–06 是固定历史事实，其后的接续链标明 `SYN:` / synthetic，不是真实事件。文内记载 Kimi 审查出两项缺陷后修复，新上下文 180 项通过；该结果是记录/查询规则的回归，不是真实接续收益。对应归档目录（`artifacts/agent-task-state/archives/t12-object-stage-2026-11-01/` 等，后来应在 `evidence/`）在 2026-11-13 的工作区盘点中没有找到，因此 180 项等数字只能当作文档记载，不能直接写进论文。

T12 自己给出的下一步已经是：用一个真实 Agent 小任务实际接续，观察这些规则在连续小步里是否仍然直接，而不是继续完善固定 T12 材料。这与现行 Intention 一致。

## 合起来看

已经走出来的，不是一套完成的元操作系统，而是三条仍然站得住的约束：

1. 不要把每次工具输出都升级成工作状态；普通文档对照必须保留。
2. 「前版变成后版」不够；尝试、成果修订、责任和认识要分开，当前采用必须带范围。
3. 五类对象加 Change 能编码已整理案例中的这些区别，并且有可执行的离线规则；最小性未锁，真实收益未测。

还没有走出来的，正好是论文现在缺的部分：一句话主张、可执行的对照协议（有该语义层 / 只有普通文档或轨迹），以及一次 Context 受限或清空后的真实小任务接续。离线检查器可以继续为这次接续提供记录和查询，但不应该再靠扩大对象修订来证明正确性。

DSH 相关材料仍在 [`experiments/dsh-process/`](../../experiments/dsh-process/) 与调研目录，只作为验证材料和灵感来源。
