
# 真实开发活动调查：首批材料筛选与覆盖

状态：已归档

本轮从真实开发活动出发执行 G1，不用三个元操作筛选材料。已获得七篇实证研究全文、四类公开项目过程以及一份作者发布的 Agent 示例轨迹，足以开始首批活动归纳。它们不构成行业代表性样本，也没有达到检索饱和；来源扩展保持开放。

## 材料怎样互补

| 材料 | 本轮实际读取与用途 | 不能推出什么 |
|---|---|---|
| Meyer 等的开发者生产力研究 | 观察方法、任务/活动定义、结果及局限；开发者如何跨任务和活动工作 | 工具切换次数不能直接等同于有害中断，个人感受不等于客观任务质量 |
| Sillito 等的软件演化问题研究 | 两类观察设计、问题分类、工具组合与局限 | 一个搜索命令不能代表完整的理解活动；历史分类也不是我们的固定模式 |
| Ko 等的团队信息需求研究 | 方法、任务结构、信息寻求、阻塞与局限；含混合修改需要分离的直接观察片段 | 研究中的参与者数量和场景不支持全行业活动频率 |
| Bacchelli / Bird 的现代代码审阅研究 | 方法、动机、实际结果和理解困难 | 审阅通过不意味着找全缺陷，也不能把所有评论都视为待改代码 |
| Silva 等的重构动机研究 | 方法、动机分类、开发者回答及工具限制 | 相同重构动作可以服务不同目的，不能仅看 diff 自动判定动机 |
| Parnin / Rugaber 的恢复策略研究 | 会话定义、策略、编辑延迟及有效性威胁 | 会话开始不一定是恢复旧任务，首次编辑延迟也不是纯恢复成本 |
| Python PEP 703 的接受说明及 PEP | 2023-10-24 有主体和条件的决定、阶段推进、兼容性与回退边界 | 本次读取的 PEP 当前状态不能倒推 2023 年已经实现了什么 |
| Kubernetes sidecar 的发布说明、KEP、Issue 753、PR 120620 | 用例边界、alpha 已知问题、生命周期修订、审批/hold 和后续义务 | 当前 KEP 是后来修订过的文档，不能当作每个历史时点的输入；没有完整重跑 CI |
| curl CVE-2023-38545 公告及修复 patch | 缺陷条件、修复版本、缓解、报告与协调发布顺序 | 未公开的私下诊断讨论不能靠补故事恢复；本轮不执行漏洞或修复 |
| GitLab 2017 数据库事故复盘 | 时间线、尝试及失败、恢复、改进清单 | 是一手事后报告，不是事故发生时的信息快照或独立审计 |
| SWE-agent marshmallow-1867 示例 | 官方文档所嵌 14 步 JSON、工具观察、编辑拒绝与重试、提交 | 是 v0.7.0 作者示例/回放，不是新实验、长程压缩样本或独立评分通过 |

正式出处、年份、venue 与版本唯一见[source-inventory 的本轮登记](../../docs/specification/change-graph-task-state/source-inventory.md#2026-10-15开发活动调查来源)。七份全文为 Meyer 的两篇论文，以及 Sillito、Ko、代码审阅、重构和恢复策略研究。作者 Work Life 博客和 CHI 恢复提示页面只作补充入口，没有冒充全文精读。

## 探索与保留

探索过程固定为 Python、Kubernetes、curl 和 GitLab 四个项目背景；SWE-agent 示例是额外的 Agent 工具过程材料，不与自然项目过程混成独立同分布样本。已读案例和既有 SCBench 片段登记为已暴露。

Django 和 VS Code 是两个候选保留项目，仅尝试获取仓库元数据；直连 TLS 失败，尚未完成过程可用性筛查，没有精读其 Issue/PR 或作为验证材料使用。G5 开启前必须确认可用性、选择实际过程并冻结规则；当前不能声称保留验证已准备就绪。模型训练中的先验接触无法排除，“保留”只指本轮不参与设计。

## 覆盖与缺口

| 检索方向 | 已有过程或实证支持 | 本轮剩余限制 |
|---|---|---|
| 目标、要求、方案边界 | Python 条件式接受、Kubernetes 用例与行为边界 | 商业需求发现和用户协商仍薄弱 |
| 理解系统、影响分析 | Sillito、Ko、Agent 定位代码 | 大规模跨仓影响还未按真实完整链编码 |
| 实现与重构 | Agent 修改；重构动机研究；curl patch | 重构问卷不等于我们逐项目重放其全部历史 |
| 审阅、协作与授权 | 代码审阅研究、Kubernetes PR 的 hold/approve/lgtm | GitHub 折叠评论和删改内容可能缺失 |
| 测试、诊断、环境 | Agent 复现和编辑拒绝、GitLab 诊断与恢复 | CI 全量结果和长期随机失败未重验 |
| 发布、迁移、兼容 | curl 协调披露、Python 分阶段推出、Kubernetes alpha 限制 | 跨版本迁移的完整执行轨迹仍需补充 |
| 维护、事故、后续义务 | GitLab 复盘、Kubernetes 明确延期及重构义务 | 单次事故不代表维护的自然频率 |
| 中断、等待与接续 | Parnin、Ko 的信息阻塞，Kubernetes hold | 没有多轮 Context 压缩的实际 Agent 轨迹 |

公开过程没有覆盖的现象继续保留为研究目标，不能从首批材料中排除。没有压缩轨迹不阻断初步活动归纳，但阻止宣称已经检验长程 Agent 接续效果；没有保留过程不阻断探索，但阻止 G5 验收。

## 本轮筛选与验收

检索分三轮：先找实际工作和中断的实证依据；再扩展信息需求、重构和不同性质的项目过程；最后核对全文、发表身份及真实产物。第三轮仍在补证据，不当作“无新类别”的饱和轮。搜索结果中的职业介绍、二次解读、Reddit 与 ResearchGate 不承担核心事实；有官方原文时使用原文。任务规格和轨迹 schema 单列，不能冒充真实执行。

G1 首批验收：通过，允许进入 G2 探索归纳，保留上述范围限制；不宣称广搜结束或整个生命周期已完整覆盖。通过依据为三路来源已实际读取、探索过程有起点/变化/结果或最后可见状态、关键材料角色已区分、未解决限制不会被用于更强主张。若后续分类依赖未覆盖过程，回到 G1 定向补搜。
