
# 工作管理元操作候选 v0.3：记录、引用与范围内选用

状态：已归档

2026-10-21 定位更新：本页保留记录层规则。当前工作操作研究见[首轮推演](../experiments/operation-composition/work-operation-study-v0.1.md)，下文离线检查器建议已由“先明确工作转换契约”替代。

**本版建议以三项记录能力组成工作历史：保存可定位的版本，连接有意义的精确引用，在明确范围内更新当前选用。**它们可以共用一个登记底层；暂停、部分撤回、复用和修正判断由这些能力组合。

这个判断来自 DSH 全部 16 段过程的同作者走查。最重要的观察是：相同工作会同时保留不同成果、修订、解释和验收状态。Loader 撤回事务回滚仍保留独立修补；预设更新后旧运行修订仍被持有；聊天分组基础实现后产品验收仍未完成。记录机制需要保住这些区别。

[组合推演与删减依据](../experiments/operation-composition/operation-composition-review.md)保留 Loader 详细过程、80 项人工回答和 14 个有限反例。普通文档保留相同约定后同样可表达这些内容。本版没有证明全局最小性、维护收益或长程接手收益。

## 三项能力怎样配合

| 能力 | 保存与改变什么 | 从哪里看出必要性 |
|---|---|---|
| 可定位的记录版本 | 工作、提议、实施报告、观察、判断、责任等内容及历史修订 | 终端新归因出现后，旧解释与失败测量仍需查；只留最终状态会丢失路径 |
| 有范围的精确引用 | 指向具体修订或修订内定位符，记录来源、取用范围及关系含义 | 预设工作 ID 不足以区分旧运行修订和新定义；E2B 退出只保留部分接口 |
| 带前提的范围内选用 | 谁依据什么，改变哪项安排或当前解释；旧选用历史保留 | 两轮 Goal 暂停政策需沿同一范围更新；选择报告不等于现实执行或授权 |

三项能力是待检验的语义划分，不规定必须三个函数或三张表。暂停一条路线时，可以保留成果，追加暂停决定，修订该范围的安排；复用时，引用具体成果及取用条件，再登记新的方案。含义由记录与规则共同承担。

## 本轮确认需要写清的八条规则

| 规则 | 具体要求 | 删除见证 |
|---|---|---|
| R1 历史与定位 | 旧内容可寻址，引用固定修订；目录可重建，引用不能悄悄转向新版 | D01 终端历史、D02 预设修订 |
| R2 范围与条件 | 说明作用于哪个部分、使用者、环境或阶段；语义范围由调用者提供 | D03 重启条件、D10 局部撤回 |
| R3 报告与证据归属 | 提议、决定、实施、观察和验证分别表述；保留作者报告、研究判断及未知 | D04 基础与验收、D11 接纳与完成 |
| R4 选用域 | 当前解释、工作安排、执行授权和现实结果分别记录；不相互自动推导 | D05 目标与运行、D14 执行与清理 |
| R5 修订前提 | 修订说明来源版本；选用更新核对旧配置，过时请求重新解释或协调 | D08 过时暂停政策，属于构造探针 |
| R6 可见时间 | 事件时间与来源可见时间分开；复合断言拆分，或等待全部支持来源 | D07 旧提交与后来的回顾解释 |
| R7 主体角色 | 决策者、执行者、报告者、整理者分别保留；缺失主体写未知 | D06 署名误当决定者 |
| R8 关系意义 | 保存谓词、范围及依据；共享不等于因果或保证继承，变化不自动等于失效 | D09 共享、D12 旧 UI 适配、D13 撤回原因 |

规则的文字内容需要调用者判断。程序可以检查声明是否完整、引用是否存在和版本前提是否匹配，不能证明所有依赖均已找到或自然语言判断正确。

持续责任和未完成事项也分别记录：消费者每次应检查激活是一项长期约定；某次消费者适配尚未完成才是一项待办。不能因未来仍有修补就推断此前工作全部未完。

## 谁负责什么

| 角色 | 本轮规定的责任 |
|---|---|
| 调用者，人或 Agent | 声明工作身份和变化边界、选择关系含义、识别依赖及兼容性、提供判断与依据；超出权限时请求有权主体决定 |
| 核心登记程序 | 保留不可变历史，校验精确引用、类型、已声明权限与前提；接纳成功后提供确定的查询与当前投影 |
| 视图生成器 | 按读者和范围组织已有记录，区分当前选用与历史报告；新解释作为候选交回登记 |
| 外部执行层 | 实际编辑、测试、投递与部署，返回有范围的结果；数据库登记不能替代这些动作 |

工作库、语义维护器、视图生成器继续作为已有架构假设。本轮明确其责任，尚未证明三个组件是最优数量。

## 对 v0.2 的取舍

保留版本、精确引用和选用前提；将独立工作目录改为可投影索引；来源关系允许内嵌。关系需被独立安排或复用时再建立独立身份，否则使用容器修订与关系定位符。清单项需要独立推进或验收时可声明为子工作，其余保留稳定定位符。

创建、修订、分叉共用新增版本的登记形态，身份判定仍属调用者责任。整合是高阶过程：识别取用范围和必要依赖，处理冲突，形成候选并决定是否采用。多父引用仅保存来源，不保证兼容。

关系可以共享登记规则。本轮 12 种关系名称按维护方式归组后仍需保留原含义，暂不冻结一个更少的关系词表。自动判断身份、自动传播失效、自动协调语义冲突均暂缓。

## 下一阶段原型建议与停止条件

**建议下一阶段只实现一个离线记录检查器，用于验证这些声明能否被程序一致执行。**输入是已由调用者解释的记录与更新，输出为接纳结果、缺失引用或前提冲突、指定范围的当前投影和证据入口。它同时读取强文档表示与结构化表示，避免把阅读格式等同于系统能力。

原型重点验证旧引用保持可查、同范围旧请求被识别、不同状态轴互不覆盖、关系修订历史可重建。并发、权限和失败接纳需用明确构造用例测试；真实外部执行与自动语义解释不属于该建议。

如果真实过程的局部范围仍只能依靠每次临时解释才能维持，先改进调用者声明与规则，再评价原型。若强文档在相同规则下更易维护，就保留这一结果。长程任务收益留待独立接手和 SWE-Milestone 验证。本版不授权实现原型或付费调用。

### 接口形态

语义显式接口沿用候选：

```text
derive(identity, parents, content)
relate(kind, endpoints, scope, justification)
select(scope, expected_config, next_config, decision)

prepare(base, delta)
record(expected, delta, actor, request_id)
```

这些是候选接口，不是已实现 API。前一组是语义包装，后一组构造并接纳同一内容。prepare 不改变权威状态；record 成功表示记录接纳，不表示外部动作已经完成。未持久化 prepare 时，仍须保存足够的完整 delta 和检查依据。

记录最少能够定位身份/修订、内容类别、所针对对象及范围、精确来源、报告/整理主体和时间。字段可内嵌，不要求每项单独对象。记录是否需要原子成组由一致性需要声明；未知依赖不得伪装成已检查。

### 身份、引用和关系修订

- 创建：新身份、无父版本；修订：同身份、新修订、明确父修订；分叉：新身份、引用起点。调用者提供为什么需要独立跟踪的理由。
- 引用固定记录修订，或使用“容器修订+内部稳定定位符”。引用内部内容时保留必要条件，不能只引用工作名或会漂移的行号。
- 内嵌关系修改生成新容器修订，独立关系修改生成新关系修订；两者均保留旧端点和替代范围。旧引用继续解析旧内容。
- 依赖变化可产生复核候选，不能仅因前提版本变化就登记结论为错误。判断失效须有对象、范围、依据和主体。

### 选用与冲突

沿用 v0.2 的一份配置串行接纳作为协议候选。局部请求从明确 base 构造完整配置，核对 expected、引用、已声明权限与约束后整体接纳。冲突时保留候选，不接纳其中方便的一半。无冲突的旧请求也须以新前提重新检查，不采用任意自然语言的自动三方合并。

scope 由调用者声明，包含选择域与适用范围。相同键的更新可机械检测；语义重叠不能由字符串不同自动排除。未知重叠转为协调事项。已有明确规则与权限可由程序或 Agent 处理；改变意图或超权限时交有权主体。相同 request_id 而不同内容须报告冲突。

本轮 Loader 的 select 只更新研究者当前解释入口。它不是原工程选择的重演，也不改变实施报告。若以后用于真实记录，必须显式声明选择域为工程安排并取得对应授权。

### 组合与语义读回

| 动作 | 记录组合 | 应能读回 |
|---|---|---|
| 部分撤回 | 保存决定与实施报告，引用撤回及保留范围，更新相关安排 | Loader 回滚退出、独立修补仍在、中间失败与后续适配 |
| 暂停/恢复 | 保存有主体的安排修订，保留成果和恢复条件，更新该范围选用 | 暂停不等于成果错误；持久目标不等于运行授权 |
| 局部复用 | 引用来源成果及条件，保存新候选和依赖，决定是否选用 | E2B 实现退出，接口继续使用，不继承全部假设 |
| 判断修正 | 保存新观察与新解释，连接旧解释及作用范围，修订解释入口 | 终端旧测量可查，本次故障采用新归因 |
| 拆分推进 | 保存分解与来源，为独立工作声明身份或清单定位，分别记录验收 | 聊天基础落地，产品 GUI 和性能仍未验收 |
| 旧方案适配 | 保留旧来源，引用变化后的依赖，形成适配候选 | 旧反馈 UI 需重写，已落地后端继续使用 |

验收以[完整走查](../experiments/operation-composition/operation-composition-review.md)和固定过程底稿为对照。新执行者应能解释上述组合及责任；本轮未执行独立新执行者盲测，文档自足检查不等于已测得接手成功率。
