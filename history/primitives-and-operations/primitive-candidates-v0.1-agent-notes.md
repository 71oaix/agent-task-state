JJ 官方术语明确 Change 本身不是独立数据对象，change ID 是 commit 属性。借用稳定身份的设计不要求复制对象布局。未选用、隐藏、放弃与删除在本系统中也不能机械映射 JJ 同名操作。

Datomic 特别强调已发生事务不能任意拆分或合并，因为会改变时间与领域含义。候选设计的“组合”首先是组装一个待登记变更包，不是重写已发生的历史操作；运行顺序有业务意义时保留多个独立记录。

## 两个候选的精确定义

两者共享一个候选状态模型：已保存的不可变版本集合 R、有类型且可定位版本的关系集合 L、各任务/工作范围当前选用的配置 P，以及登记历史 H。对象身份与版本身份分开；P 引用版本，不复制其内容。方案状态、执行安排、证据结论及生命周期不压成一个互斥状态枚举。此模型是研究建议，不是已批准 schema。

**语义显式版**由三类写入动作及读取组成：

- 生成版本 `derive(identity, parents, content)`：创建新的版本身份，旧版本不变；保留目标工作的稳定身份或明确分配新身份。parents 包含演化来源，不默认形成支持关系，也不自动接纳父版本全部主张。同身份并发修订可以共存，不能假设工作 ID 唯一定位一个最新版本。
- 建立关系 `relate(kind, endpoints, scope, justification)`：引用存在的精确版本；来源、任务包含、必要依赖、支持组、冲突及主体责任由类型规则区分。关系也需稳定身份和修订历史，可用关系对象实现，不能原地删除旧解释。支持组内部合取、独立支持组之间析取；自然语言 support 不自动变成形式蕴含。
- 改变选用 `select(scope, expected_config, next_config, decision)`：生成新的配置版本及决策记录；引用所需版本和关系，程序原子检查旧配置及必要读依赖。选用 scope 可以包含多项并行工作。请求过期返回冲突/待协调，候选成果继续保存；不最后写入获胜。选用工作与宣告事实真值不同。
- 读取 `read(version_or_config, projection)`：指定不可变版本/配置读取，查询关系与历史；Human/Agent 视图是投影。自然语言摘要若引入新判断，应另行生成候选记录，不能通过读取改写 P。

父来源可以为空：创建；单来源同工作身份：修订；单来源新工作身份：分叉；多来源及明确取用范围：整合。这是候选动作的归约，不是已证明所有复杂整合都满足同一算法。内容生成/工程合并可由工具、LLM 或人完成，元操作负责登记其输入、输出和冲突，不负责凭空完成推理。

**事务统一版**把 R、L、P 都编码成版本化数据，以 `prepare(base, delta)` 构造并检查候选变更，以 `record(expected, delta, actor, request_id)` 原子登记。只登记新成果时 P 不变；明确包含选用更新时才改变 P。读取相同。构造是无副作用的函数，持久副作用集中在 record；因此不能将它与三种语义动作简单按“函数数量”比较。语义显式版的动作也应能组装成一个事务，禁止显示出只更新安排却缺失决策依据的中间状态。

两者可以共存为上层语义接口和底层登记机制，不必强制二选一。若 relate/selection 编译为普通数据，完整类型规则与约束仍是核心的一部分，不能从“最小”计算中藏掉。

## 纸面组合检查及反例

已按用户讨论的功能逐项推演，未执行代码：

1. **保留性**：A2 修订为 A3 后，测试 T 仍准确引用 A2。若所有关系仅引用工作 A 并自动解释成最新版本，反例立即成立；故引用精确版本是必要约束。
2. **选择与证明分离**：优先 B 的决策仅改变安排。若自动加上 A 不成立，语义错误。选择配置的改变不传播为技术结论。
3. **并发不丢失**：两人基于 P0 各自提交。两份成果可登记；对同一配置的选用更新不能都假装基于未变化 P0 成功覆盖。不同 scope 是否独立，仍需检查共同读依赖与全局约束。
4. **部分复用**：A3 只取 B 的组件 X。来源指向 X 及必要依赖，不能以 B 为父就继承 B 整套假设。仍需明确组件边界与语义依赖识别，是主要未决点。
5. **局部冲突**：同一假设环境内形式矛盾禁止同时视为已证明；跨环境的不同结论可以并存。自然语言争议另存未决状态，不能让程序依据标签消除它。
6. **撤销与重放**：错误关系通过新修订退出当前选用，旧记录保留。重建相同 H 及规则版本应得到相同已接受状态；LLM 不参与重放历史裁决。真实外部副作用不因重放而再执行。
7. **幂等边界**：相同 request_id 重试不重复记录已完成登记；两次独立、同内容的决定可以保留为两个事件。不能用“状态值相同”吞掉真实第二次决策。
8. **完成与技术债**：交付记录引用接受范围，债务是仍可跟踪的义务关系；缺失支持不是失败，用户接受 MVP 也不使全部债务自动消失。

这些检查支持继续推敲操作区分，不构成完备性、必要性形式证明或效果结果。候选缺少执行资源调度与真实工具取消；这些由执行层消费安排并写回观察，不能宣称现有元操作已经管理所有外部效果。
