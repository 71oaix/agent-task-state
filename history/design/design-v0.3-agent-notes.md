
# 架构设计 v0.3：Agent 接手与依据

状态：已归档

人类审阅入口是[架构设计 v0.3](design-v0.3.md)。架构行为与取舍以该文为准；本文补充维护、接手和证据边界，不独立改变架构。如果技术细节实质影响正确性、成本或关键选择，必须转译回审阅稿，不能借分层隐藏。

## 本次修订及维护方式

2026-10-11 用户明确要求按读者区分文档。原[v0.2](design-v0.2.md)混合架构、来源与接手信息，本次改为两份同版本文档。v0.1/v0.2 原文保留，不把表达改进包装成新增方法或实验发现。

审阅稿由问题、整体关系、组件职责、路线切换和压缩后的行为组织。前版的技术约束按下文保留；论文来源不在主文逐项堆列。以后用户讨论架构时先改审阅稿，同步有影响的接手约束；接手者先读主文，再按当前工作读取本说明、来源和历史。

本项目采取这一阅读分工：审阅稿服务用户理解设计和作关键判断；Agent 说明服务版本维护、来源核查和后续执行。它们引用同一架构，不维护相互竞争的规格。用户关于 docs skill 的想法尚未构成修改全局 skill 的指令，本次不修改安装规则或记忆。

## 必须保留的技术约束

- 历史中保存不可重建的结果和被接受的判断，原始成果引用固定版本并保留必要内容。仅有路径或哈希不足以恢复；不把所有日志都提升为任务事实。
- 修正追加记录，不覆盖过去。依赖、支持、反证和取代关系区分语义；暂停、采用、验证程度与完成程度不能合成一个状态。
- 按固定规则应用已接受历史恢复状态，不重新调用模型生成历史判断。记录和更新规则均有版本；规则升级不能静默改变过去。
- 状态维护器处理并行提交的出发版本，发布记录与当前状态保持一致，防止过期覆盖和重复登记。图里历史到现状的箭头包含应用更新规则，不意味着无规则自动推导。
- 外部动作请求与结果分别保存。崩溃后结果未知先核对，不盲目重试；幂等能力取决于外部工具。恢复状态不能自动回滚现实环境。
- 保留适用条件版本或时段与系统获知时间，未知不补造。历史决策评估只用当时可获信息。
- Agent 提出的判断单独保存。写入校验保证结构及权限，不证明其内容真实；测试失败也不自动证伪整条路线。
- 自动传播只覆盖已知依赖。复杂结论由 Agent 或人复核，其已接受结果持久化；关键待复核结论不能呈现为新条件下已确认。
- 视图不承载唯一的新判断。普通摘要可重生成，但当时实际发送的视图与取回记录若用于评估，需要另存，历史状态不能代替模型实际所见。
- 保存未成功不得声称已有恢复点。Context 容量不足时暴露缺口、收窄工作，不能静默省略约束。

前版的历史恢复、时态、并行和外部副作用边界均由上述约束延续；简化主文并未删除这些设计要求。它们目前均是设计要求，不是已实现能力。

## 来源和已知证据边界

设计意图来自用户[阶段性总结](../docs/research/change-graph-task-state/design-hypothesis.md)、[数据库韧性设计讨论](database-resilience-discussion.md)及本聊天后续关于 JJ、摘要、版本依赖和读者分工的意见。对话吸取记录已按复制文本补齐七轮，不能沿用“接口返回五轮就是全文”的旧说法；原始个人文本不提交。

直接近邻的核查见[近邻报告](neighbor-review.md)，固定来源、venue 与阅读深度见[来源清单](../docs/research/change-graph-task-state/source-inventory.md)。MAGE、StateMem、InfiAgent 已有相关原文审读，未复现；新六项参照工作尚待身份、原文与代码核验。不能把用户提供的对话里助手的评价作为文献事实，不能由组合机制宣布创新成立。

历史小例是手工构造，不代表复杂开发；v0.3 中的 A/B/C 是用户情境的设计推演，不是执行证据。未选择正式实验任务、模型、次数或评分器，未运行付费实验。

## 后续工作的顺序

先核验六项参照工作的实际问题、机制、价值、局限和评测范围。任何候选机制先说明不用它会导致什么失败、已有机制是否能承担、维护代价是否合理，再决定采用。

继续细化必要依赖和一般支持的更新规则，选择真实复杂任务检验压缩和路线演化；同资源普通摘要为必要对照，历史与维护日志独立于效果结论。新观察形成下一设计版，记录相对当前版的实际变化，不能靠增加栏目制造推进。

实现与实验须按项目授权单独界定。当前不是已批准 Specification Package；不进入实现，不继承工具反馈管理项目的模型、预算和工程权限。

文档检查限本次新文档及受影响入口、索引和引用。技能操作留痕使用本说明和 Git，遵循项目约定，不写工作区外全局日志。
