
# 研究问题卡：预算受限时的有效证据视图

状态：已归档

## 一句话问题

**当任务意图或环境发生变化、完整状态又超过 Context 预算时，Agent 应保留哪些仍然有效的证据、取回哪些细节、重新验证哪些结果，才能正确继续当前工作？**

这是近邻核验后保留的候选问题，尚未证明创新或有效性。用户授权本轮核验、手工示例与问题卡，不等于批准下列实验。

## 为什么值得检查

[task 0 示例](traceable-example.md)区分了两种修订：数量减少可以复用同月完整排序；月份变化需要新结果，但导航经验可保留。研究关注的是“选择性复用与重新取证”，避免全部重做或照旧继续。

该小例用状态表即可解决，不能支持新方法。若真实长前缀仍然被简单状态表解决，则无需 Change Graph。候选价值必须来自真实预算约束下，简单视图丢失了行动必需的证据关系，且可检验地影响后续行动。

## 候选机制（待验证）

输入：当前有效目标、下一步待解决问题、带作用范围的状态/证据、已接受效果及工作预算。

先找下一步所需证据，再沿必要依赖补充条件；明确分为可复用、待观察确认、需重新取证。预算不足时保留约束与缺口提示，通过工具取回必要细节。历史失败只有在失败条件仍适用且影响当前选择时才优先进入 View。

与 StateMem 的差异不能只叫 needs_recheck：要检验在在线行动里，如何在“保留/取回/重验证”之间选择，以及总成本和质量。与 MAGE 的差异不能只叫 branch hints：要检验预算内的跨分支证据选择是否提供额外收益。与 CFRC 的差异不能省略义务：视图节省不能改变残余合同。

暂不规定学习算法、图数据库、模型或产品界面。若算法只需表格字段就能实现，应采用更简单表示。

## 最小、公平的区分性验证

第一步不是跑大 benchmark，而是从已公开任务中取得一个固定的真实前缀，审查是否存在可复用证据与过期证据混合的情况。选择任务不得依据候选方法已成功；不足预算时先检查正常前缀是否真的形成压力，不人为堆垃圾撑长。

随后用同一模型、同一环境状态、同一可见证据、同一总预算比较：

| 对照 | 用途 |
|---|---|
| 当前字段表 + 近期观察 | 强简单基线；允许保存失败假设与来源 |
| 固定 schema 状态 + 普通检索 | 检查普通相关性是否足够 |
| StateMem 式依赖失效标记 + 固定渲染 | 检查状态更新规则是否已经解释收益 |
| MAGE 式当前路径 + 分支提示 | 检查已有结构性视图是否已经足够 |
| 候选行动视图 | 检查具体选择策略的增量 |
| 候选去掉关系、去掉有效条件、改为等长随机/相关选择 | 区分关系、有效性与额外 Token 的作用 |

这是逐步适配清单，不要求一开始完整实现所有系统。手工标准状态用于隔离视图效果，须标明 oracle 边界；最终需要自动状态维护评价。不能把模拟的 MAGE 式模板称为原论文复现。

同一前缀要冻结可见证据，不能把中断后的答案或 hidden evaluator fields 注入状态。预算分层包含不发生截断的宽预算对照；总成本包含状态提取、生成 View、检索、重验证、恢复与失败请求。

## 评测选择与指标

首选核验 InterruptBench 的公开意图修订任务和回放接口；ContinuityBench 可提供目标不变的恢复协议思想，但尚未取得其公开断点包。StateMemBench 是辅助状态正确性检查，不能据问答分数声称改善工具任务完成。

主要指标：原生任务成功与独立的当前意图满足；过期证据导致的错误行动；正确复用率与不必要重做；缺证据时是否恰当地取证；完整模型用量和工具行动开销。附加 scorer 需先验证，不因“测试过了”自动认定符合用户目标。

重新查询不总是重复错误；环境变动或证据失效时是必要验证。重复探索指标必须给有效条件和判定依据。缓存、模型接手和 Human View 暂不作为必须成立的主张。

## 可证伪假设与退出条件

H1：在真实预算压力和证据修订同时存在时，候选视图相对强简单/近邻式视图改善当前意图满足，或在不降低质量时减少总开销。

H2：收益来自有效条件与依赖信息，而不是更多 Token、后验挑任务、人工 oracle 或更强模型。

否决/调整条件：普通状态表足够；StateMem/MAGE 式构建同样有效；维护成本抵消收益；只在人工状态上有效；无法找到既有任务里的实际失败；只能在刻意构造的长垃圾前缀上成立。

若方法没有增量但现象稳定，转为适用条件实证研究；若连问题实例都没有，保留负面发现并调整方向。创新未核实不是要求立即证明顶会价值，学习和静态核验仍可继续。
